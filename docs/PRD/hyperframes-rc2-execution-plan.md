# HyperFrames RC2 执行方案

日期：2026-09-22

状态：用户已批准 WSL 实施及 Windows 工具部署；本仓库已实现候选工具与规则，并只在隔离 fixture 验证迁移。Windows 部署结果以目标根收据为准；真实 WorkStore 的 dry-run/apply、生产作品修改和删除均未执行，仍须分别取得准确授权。

验证方式：实施阶段在 WSL 内做相关单元测试和小规模 smoke 检查即可；不新增强制人工验收、Kimi 审查、Windows Studio 验收或三场景盲测门槛。既有生产作品的方向确认、Draft 接受与 Finalize 权限不因本次工具开发而改变。

本文取代此前两份 RC2 分散方案的待确认状态和执行要求，是 WSL 工具开发的 RC2 执行入口。WorkStore 中的导入来源不自动同步，后续开发以本仓库版本为准；历史评估只作为依据，不重新触发审批。

## 1. 范围与归属

仅针对 `hyperframes_video` 解决文字信息取舍、Scene 中间过程、新建对象过多、系列编号与定位、账号版本和临时实验混排六类问题。`podcast_quote_image` 的新建参数、三位序号、命名与工作流保持原状；共享 CLI 的修改不得改变该分支。不建设新数据库、第二个播放器、资产评分平台、发布系统或长期样例库。

WSL 修改 canonical 工具及规则源，不直接修改 Windows 安装中的 runtime/.studio，不编写生产 Scene。本文中的 `.studio/work.py` 等路径是当前安装模块的定位线索，开发时在实际 canonical 仓库定位对应源，不假定源仓布局相同。

## 2. 对象与新建边界

| 对象 | 定义 | 使用条件 |
| --- | --- | --- |
| Series | 正式内容的组织与编号空间 | 独立内容系列 |
| Work | 一项独立的内容目标，不是一次对话或实现尝试 | 独立的一期内容，或重策划后的新内容目标 |
| Variant | 同一目标下需要独立制作和接受的版本 | 账号适配，或需独立维护文案、布局、时序的版本 |
| 修订 | 同一版本内持续改进 | 改字、修节奏、修布局、修代码，不另建 Work |
| Experiment | 验证尚未确定选择的临时对象，可复用 test Work 存储 | 独立效果尝试、对照或能力验证 |
| 实验 Variant | 同一实验内独立比较的方案/条件 | 原版与短入场、portrait 与 landscape 等 |

同一来源不必是同一 Work，同一主题也不必是同一 Work；以是否仍在完成同一内容目标判断，不按来源 URL 或相似标题自动合并。

账号是 Variant 的归属，不是全部身份。允许同一账号在同一 Work 下有多个 Variant，撤销当前“一账号一个 Variant”限制。

仅改变编码尺寸且不改变设计时，沿用现有输出规格，不新增层级；画幅变化需要独立布局、文案、时序或接受时新建 Variant。短版和完整版服务同一期目标时可作独立 Variant，独立策划的一期另建 Work。

## 3. 创建前分流

按以下顺序执行，不要求用户说出“测试”，不以关键词匹配替代意图理解：

1. 仅讨论、解释、研究或评估：不自动新建工程，必要时记录文档。
2. 明确继续或修改已有对象：解析准确对象后继续。同一方案修复走修订，不重复新建。
3. 同一期需要独立版本：复用 Work，创建 Variant；已有匹配版本则继续。
4. 试效果、比较方案、局部复现且无正式内容目标：进入实验区。明确要求原版不动的独立对照使用隔离实验。
5. 明确制作新的正式内容：生产新建，解析系列和账号，只补问真正缺失的信息。
6. 用途确有歧义且会改变组织或实施范围：创建前问一个简短问题，不默认生产、不同时建两份。

已明确生产任务中的“先做一幕看方向”“检查播放”沿用该生产流程，不误分流。真实素材、账号样式、生产 Current、无 Final 或未接受，均不能单独决定用途。

创建前的普通进度说明标明继续现有作品、新增版本、临时实验或正式新建。明确时不新增批准步骤。既有对象查找限定于当前对象、明确来源和相关标题/账号候选，不全库猜测相似内容。

### 工具约束

- 新建视频 Work 显式传用途，保留现有 `purpose=standard/ip/test`：`standard` 与 `ip` 是生产用途，`test` 是实验用途。不传时报清晰错误，不默认为生产；播客新建不受此约束。
- 不把 test-work 新增成 workflow 枚举；继续使用实际内容 workflow。
- 新生产视频对象要求有效系列和账号；视频实验不绑定账号，准确账号配置只作参考快照。内部 `test` 标记不作为生产系列编号空间。
- 工具拒绝重复 ID、系列号冲突和非法归属，不声称能判断自然语言真实意图。
- 旧缺字段 Work 保留 legacy 读取兼容，不因新建约束而整体判非法。

## 4. 系列编号与定位

- 生产视频 Work 保存独立 `series_number`，`WORK.md` 标题只保存语义名称，不强制添加全局 Work 号；系列号不得从 Work ID 或标题推算。
- 首次对当前仍保留的旧生产视频 Work 按旧 Work ID 数字顺序分配，含已归档作品；所有 Variant 共用一个号。系列号数字至少三位显示，不限制到 999。
- Work ID 与系列号各自分配。当前仍保留的旧视频 Work 做一次身份迁移，例如 `work-hyperframes_video-027` 改为 `work-hyperframes_video-027-Agent四大阶段`，物理目录叶名与新 ID 一致；新视频 Work 也采用全局序号加创建时语义名称的可读 ID。全局序号可扩展到四位及以上，不因到 999 而停止；名称段按 Windows 安全路径规则规范化，保留可读中文，重名由全局序号区分。标题或系列日后变化只更新元数据和导航，不再改 ID/目录；播客 ID 规则不变。
- 归档、改名和调整排序不改号；新增按系列已分配高水位递增，空号不回收。
- 全局视频 Work ID 数字段和各系列的高水位分别持久保存；可编辑 Series 配置更新不得清零或覆盖编号状态。数字段解析兼容旧三位和新四位以上 ID；无法解析的 legacy ID 保持可查，并在迁移 dry-run 中列出，不伪造数字。不从语义名称或系列号推算下一个 ID。分配和高水位更新使用现有创建/命名锁与原子写入，不以可见列表长度计算下一号。
- 明确跨系列调整时，目标系列分配新号；原系列号保留为指向同一 Work 的历史别名，查询时显示它已迁往新系列及当前编号，不将旧号分给别的 Work。原 Work 若日后删除，旧号仍占用但不指向新对象；不改写历史接受与媒体。
- 测试不分配生产系列号、不推进生产系列高水位。底层兼容 ID 是否含数字不影响这一点。
- 主显示名为 `智能体 007 · Agent四大阶段`。当前仍保留的旧视频 Work 须一次性迁移 ID、目录叶名、`WORK.md` 的 `id`/语义标题及文内标题；活动、停放和归档对象均纳入盘点，已删除对象不重建、不迁移名称。仅当旧标题前缀与准确旧 ID/已知命名规则对应时自动剥离，含糊或用户自定义名称在 dry-run 中列出，不猜测改写。
- 旧 Work ID 保留为指向新 ID 的查询别名，`--work`、`use` 等入口能定位新目录；Current 等工具拥有的可编辑指针更新为新 ID。冻结快照、历史接受、旧 Final、源媒体和 Variant ID 不改写。旧物理归档的目录叶名与 Work 元数据迁移是 RC2 的一次性窄例外，不开放日常重写旧归档。
- 系列号查询带系列；裸数字保留既有旧号语义或返回歧义，不静默解释为另一个 Work。
- 账号加系列号匹配多个 Variant 时，沿用本次已明确版本，否则展示候选；不默认 main 或第一个结果。
- 状态按 Variant 展示，不能用一个版本的 Final 覆盖其他版本仍在制作的状态。

## 5. 可读文件树与一次性路径迁移

RC2 对当前仍保留的旧视频 Work 做一次性目录与 ID 迁移，此后选择“稳定物理目录 + 工具生成可读导航”。新 ID 的数字段是全局内部序号，不是系列号；名称段是迁移或创建当时的快照，不随以后改标题、换系列或换账号而变化。ID 和目录由工具生成，不由 LLM 拼接。播客 Work 的 ID 与目录不迁移。

迁移须盘点 WorkStore 内工具拥有的可编辑 ID/路径引用并更新，包括 Current、跨 Work 来源关系及实际使用的路径索引；旧 ID 通过持久别名解析到新目录，不创建第二份可写 Work 或符号链接目录镜像。冻结历史只保留原文：其中的旧 ID 可经工具解析，旧绝对文件路径只是历史记录，物理改名后不保证仍可由文件系统直接打开。外部直接使用旧路径的链接需另行更新，不承诺文件系统级兼容。仍有运行中的 Studio、冻结请求/Review 待接受或其他依赖旧绝对路径的操作时，预检应阻止该 Work 的迁移并报告准确引用；不能为了改名重写冻结输入或静默留下断链。

现有 Work 列表/树入口统一使用可读标签：

```text
生产系列
  AI智能体
    007 · Agent四大阶段
      B · 竖版完整版
      B · 横版完整版
      C · 竖版完整版
临时实验
  S03开场节奏对照
    原版
    短入场
```

另在 WorkStore 根生成 `浏览目录.md`，列系列号/实验用途、标题、账号版本、状态及真实目录链接，方便从原生文件浏览入口快速打开。它是可丢弃、可重建的导航产物，不是身份或账号真源。相关 CLI 元数据修改后刷新，并提供重建入口；历史归档单独分组。

复用现有列表渲染和元数据 API，不建设独立前端、不复制可写工程、不创建链接目录镜像。链接由当前运行环境生成并指向新目录。完成这次迁移后，标题或账号改名只更新 Work 元数据与可读层；不再次重命名真实目录。

## 6. Variant 与账号

- Variant ID 保持稳定，新增可读版本名称；工具保证 ID 唯一，账号名称不能代替唯一性约束。
- 保留 `account`、`account_revision`、`account_settings` 和 `appearance_lock` 的归属/冻结职责，不建平行账号系统。
- 显示账号、版本名称和冻结配置版本；`main` 只是历史 ID，不代表主账号或无账号。
- 账号视图从 Variant 聚合跨系列内容，不维护第二份绑定表。系列账号列表是可选范围，更新不能自动重绑历史版本。
- 创作账号、风格预设、平台身份分别理解；本次不新增登录、凭据和发布系统，已有 delivery 信息不等于登录或发送授权。

| 状态/操作 | 行为 |
| --- | --- |
| 冻结信息完整 | 显示采用版本；服务有新版只是可更新提示 |
| 已绑定但历史版本缺失 | 显示“历史版本未知”，不补成当前版 |
| 旧生产版本未绑定 | 显示“历史未绑定”，不从主题猜账号 |
| 实验未绑定 | 正常状态，不作为生产缺失错误 |
| 补登记历史归属 | 不顺带重算画面、主题或背景，不改旧快照 |
| 显式采用新版配置 | 修订当前制作状态与冻结输入，旧接受不自动授权新结果 |
| 为另一账号制作 | 在同一 Work 增加对应 Variant，不改变旧归属 |

所有按 account 选择版本的代码同步处理多结果，不能只放宽创建而在后续仍取第一个匹配项。

## 7. 临时实验区

- 用说明用途的中文或英文名称，不要求记编号，不进入生产默认列表。
- 同名时给出已有候选以便继续；明确新建时分配独立 ID，显示名加短后缀区分，绝不覆盖。
- Variant 表示方案或条件；错误修复用修订，不每次新建实验或分支。
- 记录来源 Work/Variant/版本和准确参考配置，但不绑定生产账号。
- 可保留或按用户要求删除，不强制归档、入库、保留期限或自动清理。批准设计不是删除授权。
- 删除检查实际运行依赖；不级联删除生产、源媒体或公共资产，引用不明时说明具体问题。
- 生产采用时复制或冻结需要的结果到生产位置，不长期运行依赖临时目录。历史来源文字链接与运行依赖区分。
- 对产生实际决定的实验，在相关 Plan 或现有说明记录一句结论、原因和采用版本；无结论实验不强制报告，不建知识库。
- 不直接把实验提升为已接受生产；正式采用后仍走生产流程。测试不导出视频、不 Finalize。

## 8. 文字与节奏合同

保留四阶段、原音与对齐、稳定 Scene/Anchor ID、资产冻结、唯一宿主时钟和 Draft/Final 生命周期。仅替换设计职责与重复模板，不增加审批流程。

### 职责和顺序

1. Research 管事实、实例、素材、依据与边界。先理解完整段落，确有材料缺口才研究。
2. Plan 屏幕编辑决定必要信息、准确表达与声画分工；实际上屏表达只维护一处。
3. Plan 舞台编排决定完整区间的进入、阅读、变化、交接和退出，包含上下场衔接。
4. 实现执行采用的表达与编排，保留具体布局、图标、装饰、自然动作的判断空间。
5. 制作反馈按原因回编辑、空间、节拍或实现，不一律补字、加动画或重开 Research。

删除“等义屏幕编辑一律回写 Research”；新增事实、改变原意或证据边界仍返回权威来源。共享源修改仍检查引用版本的实际影响。控制模型负责编辑和导演判断，不改变用户选择的模型或派工提供方，不强制逐场多方案。

### Plan 两个视图

上屏信息表以完整理解单位建行，不按每句口播建行：

| 字段 | 内容 |
| --- | --- |
| 信息 ID / 来源 | Script Anchor、Research 条目或素材位置 |
| 理解目标 | 对象、区别、条件、关系或结论，不只写主题词 |
| 实际表达 | 准确文字或明确的素材原生信息/图形承载 |
| 视觉职责 | 辨认、定义、证据、条件、比较、导航或结论 |
| 声画分工 | 画面保留什么，声音解释什么 |
| 揭示与阅读边界 | 不早于哪个 cue，在哪个状态必须可读 |

Scene 节拍表引用信息 ID，不再抄写正文：

| 字段 | 内容 |
| --- | --- |
| 时间依据 / 区间 | 音频 cue、停顿或事件间约束 |
| 观看任务 | 阅读、比较、观察、跟随变化或理解关系 |
| 屏幕状态与焦点 | 已在场的对象和信息，当前主要看哪里 |
| 状态变化 | 进入、保留、移动、归组或退出 |
| 语义与阅读保护 | 尚不能揭示、不能遮挡或提前清除的内容 |

两表加整片概览替换重复章节，不新增 Shotbook、逐场审批或逐秒填表。每场覆盖进入、阅读过程和离开，行数随实际变化；证据页可为单一持续阅读状态，不强制五阶段。

### 关键原则与派工

- 舞台是角色、对象和空间关系，不是提前摆满空卡片。
- 允许完整定义、引文和关键条件，不以缩短字数代替信息充分性。
- 阅读期间稳定，读完可移动、归组和退场，不要求全场只增不减。
- 正常阅读可以静止；无观看任务的等待不能靠装饰循环、慢 tween 或复述填充。
- 新事实、条件和结果即使由图形表达也不能提前泄露；已知对象与中性空间可提前组织。
- 不强制 A/B-roll 比例；S03 的具体秒数不推广为通用时长。
- 正式音频/对齐为时间真源。Plan 维护 cue 引用和意图，cues/Binding 维护解析值，不手写第三套秒数。

brief 是 Plan 的范围摘取，携带采用信息、状态编排、衔接、时间依据与精确资产引用，不成为第二份设计。计划不可行时反馈具体冲突，不擅自删条件、填衔接句或缩字号。

缺必要信息回编辑，实际证据缺口才回 Research；关系不清回空间；阅读/交接不匹配回节拍；代码偏离修实现。正常创作观看应关注完整过程，静态字段、像素变化或 worker 完成不证明观感；但不将观看任务新增为此次工具开发的强制验收门槛。

## 9. 实施顺序与迁移

本次 WSL 开发按下表执行，不需要逐步重复审批；安装、生产迁移和删除不在本次实施范围。

| 顺序 | 工作 | 交付 |
| --- | --- | --- |
| 1 | 定位真实模型、创建/查找/编号入口、测试和 source AGENTS | 精确修改范围，不另建架构报告 |
| 2 | 视频系列号与全局 ID 解耦、可读新 ID、高水位、新建用途显式化、同账号多版本及准确选择 | 一致的数据与命令行为，播客分支保持原状 |
| 3 | list/status/树、账号聚合、可重建浏览目录 | 可读导航 |
| 4 | Router、workflow、creative、visual-design、Plan/Research 模板 | 替换冲突旧规则，不追加平行规则 |
| 5 | 历史盘点与 dry-run/apply；仅在临时 fixture 上执行 | 可重跑的编号、ID、目录及名称迁移与最小恢复支持 |
