## 1. 目标

1. 新增第三种叙事模式 `explainer`（有声动态图解），让主力模型 astra high 在 Harness 内稳定产出"有声音、有世界、有编排"的动态科普片，而不是按口播逐条揭示的幻灯片。主要口播场景由 AI 生图的系列角色与生成图片承担，机制讲解用动态图解；这一模式也是复杂精良的 IP 系列的制作基础。
2. 把 Opus 对照片里可以拆开的工艺做成框架能力，让好的做法同时也是最省事的做法：声音层、世界层、字级锚定编排、逐词字幕、正向叙事方向与活力自检；另外补上系列角色与生图的资产合同和图片动作助手。
3. 确立全框架统一的五层画面结构，本版本只在 `explainer` 模式中落地。
4. 事实、交付与工程正确性这三类硬约束保持不变。
5. 系统修订 `AGENTS.md` 等根规则，与 v3.5 和当前实际流程保持一致。

## 3. 已定决策

- `D1`：v3.5 只做"有声动态图解"，以 Opus 对照片的工艺为目标。
- `D2`：两种卡片模式 `text-led` / `animation-led` 定位为廉价矩阵账号模板，v3.5 不改变其行为、默认值与既有 Work。它们迁移到五层结构由后续独立任务完成（D11）。
- `D3`（2026-09-27 更正）：`explainer` 在 v3.5 中即支持 AI 生图与角色，用于动态图解 + 角色 + AI 生图的复杂精良 IP 系列；但不走 PDoom 路线（代码绘制角色与完整表演词汇），PDoom 路线留给 v3.6。角色形态见 D13。
- `D4`：声音素材以素材库为主。BGM 与 SFX 必须是 AssetStore 中已登记、许可清楚的条目；不做程序合成，也不调用外部音乐生成。
- `D5`：音效有独立的使用规则（第 4.5 节）。
- `D6`：音效密度取"分层节制"：优先配合重点文字、举例与转场，不设固定配额；Opus 对照片只作为上限参考。
- `D7`：`explainer` 默认生成逐词高亮的口播字幕，可按 Variant 关闭；两种卡片模式维持无字幕。
- `D8`：将上游 `hyperframes` 0.8.80 `media-use` 自带的 19 个 Pixabay 音效，连同许可与用途说明，登记为首批音效条目。BGM 由用户另行提供。
- `D9`：交付深度取最全档：规则、Plan 模板，外加五项助手（按词取 cue、字幕层、声音层绑定、可动画背景 renderer、角色与图片动作）。声音层在构建时生成原生音轨，其余由工程内运行时驱动。
- `D10`：画幅以 16:9 为主、9:16 为辅，两者都有夹具和验收；4:3 不纳入 `explainer`。
- `D11`：五层画面结构（第 4.2 节）定为全框架目标。v3.5 在 `explainer` 中完整实现，卡片模式的迁移交给后续任务。
- `D12`（2026-09-27 调整）：小红书流程已经取消，Finalize 只表示渲染出最终 MP4。`AGENTS.md` 等根规则在 v3.5 中系统修订（第 4.10 节），不再只改两条禁令。播客金句图流程的代码不动，只改规则文字。
- `D13`（2026-09-27）：角色采用"生图立绘 + 姿势/表情组 + 变换动画"：AI 按固定设定生成定妆图与若干透明 PNG 姿势/表情，登记为系列角色资产跨期复用；动作只用图片变换模拟（入场、呼吸、弹跳、挤压拉伸、按 cue 切换姿势/表情、指向），不做分件骨骼，也不做口型同步。
- `D14`（2026-09-27）：`explainer` 的主要口播场景由"角色 + 图片"承担；动态图解用于机制、结构、流程与数据的讲解。

## 4. 需求

### 4.1 模式接线

- 叙事模式增加 `explainer`：resolver、lock 校验与 CLI `--mode` 同步扩展（`.studio/appearance.py:76-77`、`:186`，`.studio/work.py:2925`）。未指定时仍默认 `text-led`（`.studio/work.py:306-309`）。
- `explainer` 只接受 16:9 与 9:16。
- 规则层把 `explainer` 列为 `purpose=ip` 的推荐模式，但不改变任何默认值。
- 旧 lock 与已冻结 Variant 保持可读，不重算 hash。

### 4.2 五层画面合同

| 层 | 内容 | 时间范围 | 规则 |
|---|---|---|---|
| 1 背景层 | 世界环境与情绪色调，可使用生成的环境图 | 全片常驻，可按章节变化 | 不承载信息；可持续轻微运动；seek 安全 |
| 2 中间动画层 | 主体：系列角色、生成图片、动态图解（对象、节点、连线、流程、图表）、真实界面与视频 | 按 Scene | 承担讲解；附着在对象上的标签随对象留在本层 |
| 3 上层动画层 | 强调与转场：高亮、光效、指示箭头、粒子爆发、转场遮罩 | 按 Scene，转场可跨 Scene | 不单独承载信息；不得遮挡第 4、5 层中仍需阅读的内容 |
| 4 文字层 | 独立文字：标题、重点句、关键数字、举例标题 | 按 Scene | 样式来自主题；阅读保护规则（累积、不挤动、读完才退出）集中在本层 |
| 5 口播字幕层 | 口播逐词高亮字幕 | 全片 | 固定安全区，层级最高，可按 Variant 关闭 |

- 叠放顺序由 CSS 决定；每层映射为一条 Studio 轨道，声音另占 audio 轨（与上游 `hyperframes-studio` 惯例一致）。
- 这份合同写成与模式无关的规范；v3.5 只对 `explainer` 强制执行。

### 4.3 正向创作方向（仅 `explainer`）

- Plan 先写全片方向，内容包括：一句话概念；叙事弧（钩子 → 问题 → 揭晓 → 机制 → 回收）；核心视觉比喻；前后对照或镜像回收；世界层的情绪弧；系列声音签名。
- 每个 Scene 写明主载体（角色 + 图片，或动态图解），以及"这一场发生了什么"：一个可见的变化、对比、连接、转化或揭晓，并写明它分别落在哪几层。
- 主要口播场景默认由角色与图片承担：角色是讲述者或参与者，图片呈现情境、比喻与例子；机制、结构、流程与数据切到动态图解。
- 关键关系必须让观众理解，可以通过图解、动作、文字或声音中的任一通道；不再以"文字是否承担定义"作为判定标准。
- 卡片模式的形式规则不适用于 `explainer`，包括默认 `text-led`、文字主导优先卡片、三种场景策略。A1（新增文字不整段复制口播，且提炼不改结论）只约束第 4 层；第 5 层字幕属于口播原文，不受 A1 约束。
- 事实类硬约束全部照常适用：不伪造界面或数据，来源可追溯，原稿数字与比喻按原意。

### 4.4 角色与生图

- **系列角色资产**：新增声明式资产 kind `character`，包含：设定（名称、外形与性格要点、系列画风描述）、定妆参考图、状态集（每个姿势或表情一张透明 PNG，带锚点与朝向）、默认状态、来源记录（生成方式、日期、Asset Brief 摘要）。由 Windows 生成并登记，走现有 pack / accept；同一身份、同一版本的内容不同时拒绝覆盖。
- **系列画风**：`character` 资产中的系列画风描述，是本系列所有生成图片 Asset Brief 的共同前缀，用来保持角色与场景图风格一致。
- **生成图片**：Scene 图片、比喻画面与环境图沿用现行 Asset Brief 授权。Plan 列出用途、数量、风格与 Brief，方向批准即一并授权；生成图不冒充真实界面、操作结果或数据证据；生成后复制进 Work 冻结。Harness 不实现图片生成器，生成由宿主能力完成。
- **图片模拟动作**：角色与图片只用变换动画：入场/退场、呼吸待机、弹跳、挤压拉伸、推拉摇移（Ken Burns）、按 cue 切换姿势/表情、指向对象；口播期间可按人声活动区间做轻微"说话"起伏，不做口型同步。

### 4.5 声音层

- Plan 中写声音层：BGM（精确资产引用，情绪与起止 cue）与音效表（资产引用、锚定的 cue、画面事件、层级）。
- 音效规则：
  1. 每个音效对应同帧的可见画面事件（出现、连接、碰撞、转场、揭晓）；画面上没有事件的口播词不配音效。
  2. 类别与画面含义一致，例如错误音不配正面结论。
  3. 优先配合重点文字、举例与转场；高能量音效只用于结构点（章节转场、核心揭晓），节奏点用轻音效，点缀少用；不设固定数量或间隔配额。
  4. 不遮盖口播关键词；重击优先放在句间空隙，或利用 hit offset 预卷；人声期间 BGM 自动避让（ducking）。
  5. 起点按音效内部 hit offset 反算，由框架 `data-start` 调度，保持 seek 安全。
  6. IP 系列固定少数签名音（揭晓音、转场音等），跨期复用。
  7. Draft 审阅必须有声连续观看；没有试听的部分明确标为未验证。
- 两种卡片模式维持"不默认新增 BGM/SFX"。

### 4.6 字幕层

- 由正式音频的字级对齐生成，显示已批准的口播文本，逐字高亮，样式取自主题 token，并按画幅设置安全区。
- Variant 可关闭字幕；关闭状态冻结在外观 lock 中。
- `AGENTS.md:11`、`.studio/spec/creative.md:59` 的字幕禁令改为只适用于卡片模式。

### 4.7 运行时助手

1. **按词取 cue**：从 `characters[]` 生成工程内的冻结 cue 数据，Scene 按词、第几次出现、在哪个 Scene 窗口内取到全局秒数。找不到、有歧义或未对齐时明确报错，不插值。
2. **字幕层**：从 cue 数据生成分组与逐字高亮，状态由时间直接求值，seek 安全。
3. **声音层绑定**：根据 Plan 的声音表生成音轨元素，自动完成 hit offset 换算与 BGM 避让；只引用 lock 闭包内的资产。
4. **可动画背景 renderer**：Background 在 `solid` / `transparent` 之外新增一种模块型 renderer。它是时间的纯函数，受宿主时钟驱动，支持按 cue 切换情绪色调参数。
5. **角色与图片动作**：从 lock 闭包中加载 `character` 资产，把第 4.4 节的动作做成按 cue 调用的预设；状态切换与"说话"起伏由时间直接求值。

所有助手都遵守现行时钟合同：单一 paused timeline，seek 安全，状态不依赖 `onUpdate`，资源进入快照闭包，不联网（`.studio/spec/hyperframes.md:10-11`、`:24-30`）。锁定的 Studio 0.8.27 已支持 `data-volume`、`hf-audio-group` 与 ducking/automation，不需要升级。

### 4.8 种子音效导入

- 新增导入命令，从本机已安装的 `hyperframes` 包中读取 `dist/skills/media-use/audio/assets/sfx/`，写入指定的可编辑 AssetSource：每个音效一个 MP3 条目，包含许可、用途说明、类别与 hit offset。之后走现有的 pack / accept 流程。
- 音效文件不进入仓库或发行包。该命令由 Windows 执行；WSL 测试只使用合成的夹具音频。

### 4.9 活力自检

- Plan 检查与 Q1 增加 `explainer` 专项：每个 Scene 都有可见事件和主载体；角色与生成图片的风格和系列设定一致；五层职责没有混用；第 3 层不遮挡仍需阅读的第 4、5 层内容；音效符合第 4.5 节；字幕与口播一致。
- `preview diagnose` 对 `explainer` 目标报告：五层宿主是否缺失、字幕开关与 lock 是否一致、音轨或角色是否引用了闭包外的资产。

## 5. 验收

1. `work new` / `variant add` 可以用 `--mode explainer` 冻结 lock；`explainer` 配 4:3 被拒绝；不带 `--mode` 仍得到 `text-led`；旧 lock 校验结果不变。
2. 在隔离夹具中，`explainer` 的 16:9 与 9:16 工程都有五层宿主；Studio 或浏览器中顺播、直接 seek、回拖到同一时刻，五层状态一致。
3. cue 助手能按词、次序和 Scene 窗口返回正确时间；缺词、歧义和未对齐字符分别报出明确错误。
4. 字幕逐字高亮与夹具对齐一致；关闭字幕的 Variant 不生成第 5 层；口播文本与 ASR 不一致的部分会被报告，不做插值。
5. 声音绑定生成的音效起点等于 cue 减 hit offset；BGM 在人声区间避让；引用闭包外的资产时失败。
6. 模块型背景在任意 seek 下输出相同画面，按 cue 切换色调；卡片模式在拿到非 solid 背景时仍然拒绝。
7. 导入命令用合成夹具生成的条目能通过 pack / validate，并带有许可、类别与 hit offset；仓库和发行包中没有第三方音效文件。
8. `preview diagnose` 能在夹具上报告缺失层、字幕开关不一致与闭包外音轨。
9. 规则测试覆盖以下内容：`explainer` 章节存在；卡片规则的适用范围已标注；字幕与 BGM/SFX 禁令已限定到卡片模式；Plan 模板包含 explainer 字段（主载体、角色、生图清单、声音层）；视频流程中不再出现小红书草稿步骤；权限边界条款仍然存在；v3.4.x 的既有规则测试按新文字更新后继续通过。
11. `character` 资产能 pack / validate / install：透明 PNG 与锚点校验通过，缺状态图或非透明图时失败；夹具工程中的角色按 cue 切换状态、弹跳、"说话"起伏，seek 与顺播一致。

## 7. 风险

- 口播文本与 ASR 文本不一致会影响字幕：以已批准的 Script 为准做字符对齐，不一致处明确报告，未匹配的字在下一个已匹配字的起点跟随高亮，不插值。
- 模块型背景的性能：夹具记录每帧耗时；超出预算只影响对应背景资产，不改宿主。
- 规则篇幅继续膨胀：`explainer` 章节以正面目标为主，形式判例不复制到新章节。
