## 1. 目标

1. 把 `text-led` 文字模式与 `animation-led` 动效模式合并为一个卡片模式 `card`，并迁移到 v3.5 的五层画面合同上。卡片模式继续定位为低成本矩阵模板。
2. 卡片模式复用 v3.5 的运行时助手（按词取 cue、字幕层、声音层绑定、模块型背景），不另建一套实现。
3. 按五层合同更新卡片组件。
4. 淘汰只为旧卡片形式存在的约束，把仍然有效的约束收拢到五层合同的对应层中。
5. 事实、交付、工程正确性与权限这四类硬约束不变。
6. 降低模型负担：给模型读的规则改为"正向方向 + 少量硬约束"，能由代码或 CLI 承担的不再写成文字；Research 与 Animation Plan 针对 A/B 与五层重构。本节目标允许破坏性修改。

## 4. 需求

### 4.1 模式合并与 lock

- 叙事模式变为 `card` 与 `explainer` 两种；resolver、lock 校验、CLI `--mode` 与控制面同步修改。
- 未指定模式时默认 `card`；`purpose=ip` 仍推荐 `explainer`。
- 新建 Work 或新增 Variant 时，`--mode text-led|animation-led` 被拒绝，错误信息指向 `card`。
- 已冻结的 `text-led` / `animation-led` lock、旧 Variant、Accepted Draft 与 Final 保持可读，hash 不重算，不自动改写为 `card`，按冻结时的规则解释。
- 账号默认值或系列设置中仍写有旧模式值时，新建 Work 或 Variant 被拒绝并要求先更新设置（D8）；已冻结的 Variant 不受影响。
- `card` 只接受 16:9 与 9:16；旧 4:3 lock 仍可读。
- `card` 的 lock 字幕开关默认关闭，可开启；旧 lock 缺省按关闭读取。

### 4.2 卡片模式的五层分工

- 使用五层宿主（背景、中间动画、上层动画、文字、口播字幕），叠放与轨道约定和 `explainer` 相同。
- A-roll 为卡片：文字在第 4 层，卡片内的图标、简图等附属装饰在第 2 层随卡片；B-roll 为完整的动态图解、视频与图片素材，在第 2 层。A/B 编排按第 4.7 节。
- Plan 按 Scene 写明 A 与 B 的实际内容、编排，以及"这一场发生了什么"及其所在层。
- 卡片模式不要求角色，也不要求生成图片。
- 背景可以选 solid、transparent 或模块型 renderer。
- 声音层对卡片模式开放，规则沿用 v3.5 第 4.5 节的七条音效规则与 BGM 精确资产引用。

### 4.3 规则文字

- 根规则中"Windows 负责视觉内容"的工作边界按 D9 修订：组件可由 WSL 或 Windows 编写，WSL 开发计划可包含组件编辑；Work 内容、生产 Current、接受状态与 Final 的边界不变。
- 根规则、workflow、visual-design、creative、hyperframes spec、Plan 模板、Router、README、WINDOWS_AGENTS 与 `capabilities.yaml` 中的"文字主导 / 动效主导""两种卡片模式""text-led / animation-led"改为单一卡片模式。
- Plan 的 A/B 编排写在逐 Scene 一节中（第 4.9 节），概览只作索引；原"场景策略与状态"字段由"A/B 编排与延续"取代。v3.5 为 explainer 写入的"主载体"表述按 D11 改为 A/B 表述。talking-head Recipe 与 hyperframes spec 中的 A/B-roll 按第 4.7 节表格改写（A 为真人出镜，B 为辅助素材）。
- visual-design 的卡片章节按五层分工重写，只保留第 4.6 节列出的仍然有效的约束，与 explainer 章节共享五层合同，不复制判例。

- 工程合同：单一 paused timeline，seek 安全，状态不依赖 `onUpdate`，资源进入快照闭包，不联网。

- `preview diagnose` 的 D1 上屏照搬定位保留，范围限定在第 4 层。

### 4.7 A/B-roll 时间结构

A/B-roll 与五层结构正交：五层管空间，即同一时刻画面自下而上怎样叠放；A/B-roll 管时间，即这一段由谁占住主画面，以及主画面在 A 与 B 之间怎样切换。A/B-roll 写进与模式无关的五层合同，按场景定义 A 与 B 的内容。

**各场景的 A 与 B**

| 场景 | A-roll（主叙事） | B-roll（辅助） | 所在层 |
|---|---|---|---|
| 卡片 `card` | 卡片：文字及卡片内的图标、简图等附属装饰 | 完整的动态图解、视频、图片等素材 | A 在第 4 层（附属装饰在第 2 层随卡片），B 在第 2 层 |
| IP `explainer` | 主要内容：文字或动态图解 | 以图片为主，以及其他素材 | A 在第 4 / 2 层，B 在第 2 层 |
| 口播 `talking_head` | 真人出镜 | 展示内容、图片等辅助素材 | A、B 都在第 2 层；B 接管时保护人脸区 |

- IP 形象（`character`）可以出现在 A 与 B 中，不固定在某一侧。
- `talking_head` 仍是画面结构 Template，不是第三种叙事模式。
- 不设 A/B 比例、时长或切换次数配额，按内容决定。

**编排**

- A → B → A：B 结束后回到 A；A 按离开时的状态原样恢复，不重播入场，未讲内容继续跟随口播揭示。
- A → B：交接后不返回。
- 旧"同场叠层"改为 A → B → A 的显示选项：B 接管期间，A 在第 4 层的文字组隐藏或虚化，由 Plan 选择。
- 旧"顺序推进"删除，已由"按口播实际起点揭示"覆盖。

**B 接管期间**

- B 的媒体放在第 2 层，附带的标注随媒体留在第 2 层；第 3 层只做高亮与转场；字幕层始终在最上层。第 3 层"不遮挡仍需阅读的第 4、5 层"规则不开例外。
- A 在第 4 层的文字组退后并冻结，不新增内容；虚化的文字不再当作可读内容。
- B 期间需要上屏的新信息放在第 4 层单独的 B 文字组中，于媒体之上清晰显示，限于与 B 相关的短标题或关键数字，遵守阅读保护，B 结束时随 B 退出。属于 A 的新要点必须等返回 A 后再加；做不到就提前结束 B。

**跨 Scene 返回 A**

- A 可以在后面的 Scene 中延续（例如 S03 的 A 讲一半，S04 为 B，S05 回到 S03 的 A）。Plan 把后一个 Scene 标注为前一个 Scene 同一 A 的延续。
- 进入延续 Scene 时，已读内容直接就位，只有未讲内容跟随口播揭示；直接 seek 进入该 Scene 与顺播结果一致。

**运行时助手与 Plan**

- 在 v3.5 宿主上新增 A/B 助手：按 cue 声明 B 区间（起止 cue、A 文字组隐藏或虚化）与 A 延续（延续自哪个 Scene、已读条目）。A 文字组与 B 文字组的显示、退后与恢复状态由时间直接求值，不依赖播放回调；助手进入快照闭包。
- Plan 逐 Scene 一节写明 A 与 B 的实际内容与编排（A → B → A / A → B、A 隐藏或虚化、延续自哪个 Scene），不记录精确秒数；概览只作索引，不重复这些字段（第 4.9 节）。

**推敲记录**

### 4.9 Animation Plan 模板

- **元信息**：Work / Variant、revision、Script / Research 引用、画幅、主题、背景、运动、模式、字幕、音频与对齐来源等由 CLI 从 Variant 与 lock 生成，模型不手填。
- **全片方向**（所有模式）：一句话概念、叙事弧、核心比喻、前后呼应、背景情绪弧、声音签名；卡片模式可以只写前三项。
- **概览**：只作索引，列 Scene ID 与一句话摘要，可由逐 Scene 各节生成；不放 A/B、编排、事件序列或上屏正文，避免第二份设计真源。
- **逐 Scene 一节**，一个 Scene 的设计只在这一节维护：
  - A/B 编排：A 与 B 各是什么，A → B → A 或 A → B，A 隐藏或虚化，延续自哪个 Scene；
  - 这一场发生了什么，以及落在哪几层；
  - A 的上屏文字：以 `screen` 块内嵌在本节，写来源、理解目标与揭示 cue；
  - B 的素材：精确引用、占位 ID 或 Asset Brief；
  - 声音 cue（如有）。
- 取消独立的上屏信息块区与 Scene 节拍表；信息 ID 保留在 `screen` 块上，供 `preview diagnose` 的 D1 与 `data-info-id` 使用。

- Plan 检查改为一份短自检单：每场有 A/B 编排与可见事件；A 文字不照搬口播；B 素材有来源或 Brief；事实边界清楚。
- 唯一参考 Scene、方向批准与后续交付两节精简保留，删除重复的流程说明。
- 派工 brief 直接转交对应 Scene 一节与全片方向；Q1 观看检查改为短清单。
- `preview diagnose`、`work` 中读取 Plan 的代码跟随新格式。

### 4.12 短视频节奏合同

写进与模式无关的五层合同，`card` 与 `explainer` 都适用。`talking_head` 中真人出镜（A-roll）的区间本身算有效画面，不受 2 秒上限约束；插入的 B-roll 与卡片段仍按本节执行。

**有效节奏事件**

- 第 2 层主体变化：元素入场、退场或状态变化；A ↔ B 切换；角色换姿势或表情、弹跳；镜头推拉摇移的开始、停止或变向。
- 第 3 层强调：高亮、指示箭头、粒子爆发、转场遮罩。
- 第 4 层文字变化：新条目入场、强调从上一条迁到当前条、关键数字变化。
- 不算有效事件：第 5 层字幕逐字推进；第 1 层背景氛围漂移；角色呼吸待机与说话起伏；持续镜头运动的中间过程。这些运动可以保留，但不能填补间隔。

**间隔与编排**

- 全片正常播放期间，包括开场、Scene 内与跨 Scene 交接，相邻两个有效事件的间隔不超过 2 秒。
- 禁止"铺开再等"：元素在各自的口播 cue 入场，不在 Scene 开始时一次摆满、之后只靠字幕推进。版式骨架与中性空间可以提前就位，承载信息的条目按 cue 出现。
- 例外：刻意的停顿（例如开场钩子或揭晓前）只能在 Plan 中逐处写明原因与区间，随方向确认一并批准；诊断仍报告该区间，并标注"已声明例外"。未写明的超限区间不算例外。
- 第 4 层的阅读保护照常：文字稳定、不挤动、读完才退出；阅读期间由第 2、3 层继续产生事件，不以牺牲可读性换节奏。
- 容量不足时按语义拆 Scene 或增加 B-roll，不靠加快文字揭示或缩字号。
- 不以无意义动作凑数：隐藏或离屏动作、空 tween、肉眼不可辨的变化、与口播无关的反复闪动不算有效事件。

**Plan 与自检**

- Plan 逐 Scene 一节中写明事件序列：每个有效事件的 cue、所在层与变化；由 cue 估算的相邻间隔超过 2 秒时，在 Plan 阶段就调整。
- Plan 自检单与 Q1 观看检查各增加一项：没有超过 2 秒的无事件区间，没有"铺开再等"。

**节奏诊断**

- `preview diagnose` 新增按层节奏定位：只统计第 2–4 层的有效事件，排除第 1 层背景、第 5 层字幕，以及角色待机、说话起伏和持续镜头运动的中间过程。
- 报告两类疑点：相邻有效事件间隔超过 2 秒的区间；Scene 开头短时间内大部分第 4 层条目已经可见、而对应 cue 在后的"铺开再等"疑点。
- 真人出镜区间与 Plan 已声明的例外区间单独标注，不作为超限疑点。
- 只输出版本、Scene 与时间范围，不判定通过；无法区分氛围运动与有效事件、或无法采样的区间标为未验证。
- 事件来源优先使用运行时助手与宿主已知的事件（A/B 切换、角色状态、cue 揭示、第 3 层强调），像素采样只作补充。

## 5. 验收

1. `work new` / `variant add` 不带 `--mode` 得到 `card`；账号或系列设置中残留旧模式值时拒绝并提示更新设置；`--mode text-led|animation-led` 被拒绝并提示 `card`；`card` 配 4:3 被拒绝；旧 `text-led` / `animation-led` / 4:3 lock 校验结果不变。

3. `card` 可使用模块型背景与声音层绑定，行为与 `explainer` 一致；闭包外资产仍然失败。
4. 隔离夹具中，`card` 的 16:9 与 9:16 工程都有五层宿主，同时包含 A → B → A 与 A → B 两种编排；顺播、直接 seek 与回拖到同一时刻五层状态一致。
5. A/B 助手：浏览器夹具在 16:9 与 9:16 下覆盖 Scene 内 A → B → A（A 隐藏与虚化两种）、A → B 与跨 Scene 返回 A；顺播、直接 seek 进入 B 区间、B 结束后与进入延续 Scene 时，A 文字组与 B 文字组的状态一致，A 不重播入场；B 期间 A 文字组不新增内容。`card` 与 `explainer` 各有一例。
6. 更新后的卡片组件能 pack / validate，声明所占的层，不自带背景或字幕层；旧版本仍可安装和读取。
7. 规则测试覆盖以下内容：规则中不再出现两种卡片模式的并列描述；第 4.4 节各项旧约束已删除；A1 与阅读保护只挂在第 4 层；事实、工程、交付与权限条款仍在；`two-template-mapping.md` 不再被规则引用；A/B-roll 以跨场景时间结构写在合同中，三种场景策略表已删除，Plan 模板的逐 Scene 一节含 A/B 编排，概览只作索引；v3.4.x 与 v3.5 规则测试中断言旧文字的用例按新文字更新。
