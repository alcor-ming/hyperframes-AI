## 1. 背景

### 1.1 v3.5.1 模型对照暴露的缺口

1. **图标没有来源。** 新旧两组的图标都是模型凭记忆手写的 SVG 路径。旧组在 70×70 画布中写出接近常见开源扳手的路径，新组在 1920×1080 画布坐标中随手拼出多边形，"工具"图标变形。隔离根的资产库为空，两组都拿不到任何已接纳的图标或模块；规则只写"普通 icon 由制作者完成"，诊断与 Q1 也没有图标可辨认的检查。
2. **节奏检查看不见自制动效。** 节奏定位只读取运行时助手通过 `__hfRhythmSources` 登记的事件，像素采样只识别文字变化。模型直接用 GSAP 编写的第 2、3 层动作没有登记，诊断把新组 1.5–4.5、4.5–7.5、7.5–12 秒报为 `unverified_custom_motion` 空档，而模型自报的事件起点最大间隔为 1.75 秒。流程也没有要求交付 Draft 前处理诊断结果。
3. **Plan 与 token 负担仍重。**
   - 新组 Plan 7,122 字符，`screen` 上屏正文只占 3%；`rhythm` 事件 JSON 占 31%，与"这一场发生了什么"的散文重复；信息块附加字段占 19%，其中揭示 cue 与事件表重复，所属画面几乎总是"A，第 4 层"；素材与声音占 8%，多为"不采用"。
   - 模型额外产出了模板之外的 `DESIGN.md`（3.3k）与自写检查脚本 `check.mjs`（3k）。
   - Plan 阶段必读规则约 1.4 万字符；Draft 阶段另读 `.studio/spec/hyperframes.md` 1.98 万字符，其中"按需资产接线"一节 8.7k 只在选中资产时需要。
   - 组件源码 `component.html` 每个约 3.7 万字符，运行时 `appearance.js` 2.2 万字符，没有简短接口说明；诊断原始采样 `probe.json` 达 24.5 万字符，摘要 `report.json` 只有 3k。
   - 场景代码全部手写，是输出端最大的部分，也是 PPT 感与图标画错的来源。

两组参考工程都是在禁用生图、声音与在线素材的条件下完成的；对照实验本身的重新设计不在本计划内。

### 1.2 资产库盘点

- 已接纳包都没有声明所在层，也不上报节奏事件；多数没有声明画幅，以 1920×1080 为验收基线。
- 可安装的表达模块多为某个作品某一场的具体比喻；通用积木（节点、连线、流程、对比、图标、图表、标注）主要停留在 limited-use 依赖与配方层面。资产库已有 `lucide-static 1.45.0`、IconPark、AntV infographic、ECharts、rough-notation 等依赖入口，但没有检索与取用入口。
- 图标一个图标一个包；开发仓 `.studio/components` 与 AssetStore 两套目录，且有内容重复；状态标记种类多；面向选型的导航文本约 34 万字符；开发仓组件中 GSAP 被逐版本复制。
- 开发仓卡片家族中，多数 `*-core` 家族没有内容插槽、时长固定、只允许小范围时间缩放，实际是固定动画原型；带插槽的家族也限定固定条数与时长。Windows 侧已批准的卡片家族源码（F01–F08）提供八种卡面风格与 `renderAt` 接口，更接近积木，但目前只作派生参考。
- 内容素材空缺：没有 BGM、没有 `character` 资产、没有图片 / 截图的登记方式；v3.5 种子音效尚未导入。

## 2. 目标

1. 模型日常使用少量通用、声明式的积木完成大部分画面，不再为每个 Scene 手写整页代码。
2. 积木天然符合当前合同：五层归属、16:9 与 9:16、主题 token、按 cue 定时、节奏事件上报、seek 安全、快照闭包。
3. 模型需要图标时从本地已登记、许可清楚的图标集按名称取用，不再手写图标路径。
4. 模型自己编写的动效无需额外标注即可被节奏诊断识别；交付 Draft 前形成"编写 → 诊断 → 修正"的闭环。
5. Plan 只保留设计必需的内容；模型每个阶段必读的规则与工具输出只包含该阶段需要的内容。
6. 资产库只有一个目录与一个机器索引，面向模型只输出接口卡与检索结果。
7. 已冻结版本与已使用它们的 Work 不受影响；事实、交付、工程正确性与权限这四类硬约束不变。

## 3. 已定决策

编号按主题分组。第 3.8 节给出与两份原草案编号的对照。

### 3.1 资产库结构

- `A1`：资产库按四层重构：通用积木（日常主力）、场景模板（建立在积木上的参数化整场）、内容素材（主题、背景、音频、角色、图片）、参考样例（不可安装，只留用途与预览，默认不进检索）。
- `A2`：现有定制型表达模块逐个评估：能泛化的改写为积木或模板，其余降为参考样例。用户已确认盘点报告第 5 节的归层初稿。
- `A3`：开发仓 `.studio/components` 与 Windows AssetStore 合并为一个目录；开发仓只保留 Harness 自有积木与测试夹具，legacy 发现根退役。组件由 WSL 与 Windows 均可编写（沿用 v3.5.1 D9）。

### 3.2 图标

- `I1`：首个图标集采用 Lucide（ISC 许可）。
- `I2`：图标文件与种子音效同样处理：仓库只提供导入命令，从本机已有的图标包写入指定的可编辑 AssetSource，之后走现有 pack / accept；第三方图标文件不进入仓库或发行包。首个来源为资产库已有的 `lucide-static 1.45.0` 依赖。
- `I3`：普通图标一律从图标集取用；只有专门为本片绘制的示意图形可以自制，自制图形标为示意，不冒充通用图标。

### 3.3 卡片积木

- `C1`：卡片是事先设计好的成品部件：版式、卡面、装饰与动作在卡片中设计完成并固定；每个 Work 只在卡片预留的位置上放置不同的文字与 SVG，不改卡片设计。
- `C2`：卡片粒度为画面中的一块，同一 Scene 可以放多张卡片，并与图解、B-roll 同框。
- `C3`：卡片条数可变；容量上限按画幅与分配尺寸规定，超限明确报溢出，不缩字、不截断。
- `C4`：SVG 槽同时接受图标集中的图标与本片自制的示意 SVG。
- `C5`：入场、逐条揭示、强调、退场等动作由卡片自带；模型只为各槽提供出现的 cue。
- `C6`：首批把 Windows 侧已批准的 F01–F08 卡片家族做成正式的带插槽积木。
- `C7`：卡片的视觉设计（包括各预设 SVG 槽的位置、尺寸与数量）由 Windows 侧完成，用户选定后按插槽合同实现。
- `C8`：Plan 中卡片的位置用区域名（如 `full`、`left`、`right`、`top`、`bottom`），由 16:9 与 9:16 各自映射为实际分配尺寸；特殊情况允许写像素尺寸。

### 3.4 积木与 Plan 的关系

- `K1`：Plan 的 Scene 节中的积木数据块（首先是 `card` 块）是唯一真源，由 CLI 据此生成或更新工程中的挂载代码；模型不手写积木 HTML，Studio 中修改积木内容即修改 Plan。积木的入场、逐行出现、强调与退场由块中的 cue 推出，不重复写进事件表。图解积木沿用同一原则。
- `K2`：卡片文字直接写在 `card` 块中，每行的文字、cue 与 SVG 写在同一行；卡片之外的独立上屏文字仍使用 `screen` 信息块。卡片 ID 兼作信息 ID，供 D1 上屏核对与跨场延续引用。

### 3.5 节奏

- `R1`：节奏事件优先从宿主唯一的 GSAP 时间线自动提取，模型不需要为每个动作手工登记；氛围类动作由作者显式标注排除。积木通过助手自动登记事件。
- `R2`：节奏诊断成为 Draft 交付前的必经步骤：超过 2 秒的空档与未验证区间，在交给用户之前修正、在 Plan 事件表中写例外行，或在交付说明中逐项列出原因。诊断仍只定位，不判定通过，不替代用户观看。

### 3.6 Plan 格式

- `P1`：Plan 中"这一场发生了什么"、`rhythm` JSON 与信息块中的揭示 cue 合并为一张紧凑的逐行事件表，由工具解析；每个 Scene 只保留一句场景概括。
- `P2`：`screen` 信息块只保留信息 ID、来源锚点与正文；理解目标与所属画面默认省略（默认 A、第 4 层），只在例外时写明。
- `P3`（沿用 v3.5.1 D16；2026-09-28 按审查补充判据）：Plan 格式变化时不做兼容。CLI 在 Plan 元信息中写入明确的格式版本（例如 `plan_format`）；读取 Plan 的代码只解析本版本，缺少版本或版本不符时明确报"格式不支持"，不靠正文结构猜测新旧。已登记的历史诊断结果直接读取已保存的报告，不重新解析旧 Plan。进行中的 Work 由用户安排模型调整。

### 3.7 读取与写入减负

- `T1`：读取端减负四项全做：`hyperframes.md` 按阶段拆分；积木、组件与运行时助手提供接口卡；CLI 与诊断默认只输出摘要与文件路径；派工只传 Plan 路径与 Scene ID。
- `T2`：模型不产出模板之外的文件；检查使用 CLI 与诊断。

## 4. 需求

### 4.1 资产库结构与目录

- 四层（A1）写入资产合同与检索：每个条目标明所属层；参考样例默认不出现在检索结果中，显式请求时才列出。
- 开发仓 `.studio/components` 与 AssetStore 合并（A3）：开发仓卡片家族登记进 AssetStore，统一检索、状态与闭包；开发仓只保留 Harness 自有积木与测试夹具；legacy 发现根在合并完成后退役。
- 机器索引由包元数据生成，取代手工维护的大型索引；面向模型的检索只输出精确引用与接口卡摘要。
- 已冻结版本、已接纳记录与已使用它们的 Work 不改动；降为参考样例只改变检索与推荐，不删除包。
- 状态体系简化、导航文本替代与存储清理见第 8 节。

### 4.2 图标集导入与资产合同

- 新增导入命令，读取本机已有的图标包（首个来源为资产库依赖中的 `lucide-static 1.45.0`，含 SVG 目录与许可文件），写入指定的可编辑 AssetSource。命令只写目标源目录，不自动 accept。
- 登记形式为一个图标集资产：包含图标包名称与精确版本、许可文本、每个图标的名称、别名 / 标签、SVG 内容 hash。具体采用现有 media / module 合同还是新增声明式 kind，由实施时按最小改动确定。
- 同一身份、同一版本内容不同时拒绝覆盖；图标集升级生成新版本，已冻结的 Variant 不受影响。
- WSL 测试只使用合成的最小图标夹具；仓库与发行包中不出现第三方图标文件。

### 4.3 图标检索、取用、规则与检查

- 检索入口按名称、别名与标签检索图标集，返回精确引用（图标集版本 + 图标名）。
- 按精确引用把图标 SVG 放进工程，保留 `data-icon="lucide:<name>@<version>"` 之类的来源标记；颜色与线宽使用 `currentColor` 与主题 token，不改写路径。取用的图标进入 Variant 快照闭包；闭包外引用失败；不联网；图标集未安装时明确报错并提示导入与 accept 步骤。
- 创作指南写明 I3 的取用与自制边界；图标服务于口播内容，不放与叙述无关的装饰图标。
- `preview diagnose` 新增图标定位：报告带来源标记但与闭包内内容不一致的图标，以及未带来源标记、尺寸处于图标量级的独立小型 SVG（手写图标疑点）；只定位，不判定通过；示意图形与卡片 SVG 槽中的自制示意不计入。
- Q1 观看检查增加一项：图标可辨认、与所指对象一致。

### 4.4 卡片积木（F01–F08）

**现状**（依据已批准源码 `card-family-source@v1` 的 API 说明，只读查看）：`mount(host, options)` → `{ready, renderAt(seconds), dispose(), fit()}` 的确定性时间寻址；`frame` 指定实际分配尺寸，宽度小于 1000 设计像素时重排为紧凑布局（只改网格与内边距，不缩字）；`content` 的 `title` / `lines[]` / `note` 与各预设的可选语义槽；每行按 cue 出现并预留版面；溢出写入 `data-overflow`；外观走 `--cf-*` token；八个预设为内容优先、无前景插画列。

**需要补齐**：

- **SVG 槽**：按 Windows 侧定稿的视觉设计（C7），为每个预设加入 SVG 槽，规定各槽尺寸与两种画幅下的位置；槽内接受图标集引用与 `custom:` 自制示意（C4）。
- **五层归属**：卡片文字投影到第 4 层，卡面与装饰投影到第 2 层，与 v3.5.1 卡片组件 v2 的做法一致。
- **外观来源**：去掉卡片自带的 `theme` light/dark 与 `background` 选项，由 Variant 冻结的 Theme token 映射到 `--cf-*`。
- **时间来源**：`cues` 接受口播 cue，经 cues 助手解析为秒数。
- **节奏与 A/B**：入场、逐行出现、强调与退场向节奏诊断登记事件；接入 A/B 的退后、冻结与恢复。
- **动作补全**：补上强调迁移与退场。
- **画幅**：去掉 4:3，保留 16:9 与 9:16；区域名映射（C8）。
- **入库形态**：作为 AssetStore 中可安装的已接纳包，附接口卡；旧 `card-family-source@v1` 保留为参考。
- **验证**：补做浏览器与 Windows 原生 Studio 验证（布局、溢出、顺播、seek、回拖、两种画幅）。

**Plan 写法**（K1、K2）：

````markdown
```card C1 · P002
preset: F01
area: left
title: MCP 是一套连接规则 @连接协议 [lucide:plug]
- AI 应用是主机 @主机
- 客户端在主机里 @客户端
- 服务器提供工具和资料 @工具和资料 [lucide:server]
note: 连接不等于授权 @授权
exit: 下一场
```
````

- 首行：`card <卡片 ID> · <来源锚点>`；卡片 ID 在全片唯一。
- `preset`：F01–F08；`area`：区域名，特殊情况可写像素尺寸。
- `title`、条目行（`- ` 开头，条数可变）与 `note`：`文字 @cue [SVG 引用]`。cue 为口播词或 `词#第几次`；SVG 引用为图标集引用或 `custom:<文件>`。`@` 与 `[` 出现在文字中时需转义。
- 预设专有的可选槽（例如 F04 / F06 的键、F07 的输入与输出、F08 的层名）在视觉设计定稿后按预设补充写法。
- `exit`：可选的退场 cue；省略时随 Scene 结束或 A/B 退后。
- 阶段一：解析 `card` 块并校验语法、卡片 ID 唯一、cue 解析与 SVG 引用在闭包内，分别明确报错。
- 阶段三：CLI 据 `card` 块生成或更新工程中的挂载代码，并按定稿的卡片尺寸做容量校验，超限明确报错。

### 4.5 节奏事件自动提取

- 从宿主唯一时间线提取事件：遍历第 2–4 层目标上的 tween 与 set，按目标所在的 `data-hf-layer` 归层，取开始与结束时间作为候选事件。
- 以实际可见变化核对候选事件：在候选时刻前后采样目标的可见性、变换、不透明度、滤镜、文字与图片状态；隐藏或离屏目标、空 tween、肉眼不可辨的变化不计。
- 作者可以用显式标注（例如 `data-hf-ambient`）排除氛围动作；背景层、字幕层、角色待机与说话起伏、持续镜头运动的中间过程继续按 v3.5.1 规则排除；持续镜头运动只取开始、停止与变向。
- 运行时助手与积木（A/B、figures、cues 揭示、卡片）通过 `__hfRhythmSources` 登记事件，与时间线提取结果去重。
- Canvas、WebGL、视频等无法从时间线核对的运动标未验证，不当作静止。
- 诊断对照 Plan：列出事件表与积木块声明但未观察到的事件，以及实际超过 2 秒、Plan 中未声明的空档。
- 对照判据（2026-09-28 按审查补充）：声明事件只有写明目标时才做确定性对照——观察到的事件须落在该目标（卡片 ID 与行号、信息 ID、B 素材 ID 或元素 ID，工程中以对应的 `data-*` 标记关联）或其子元素上，且时间落在该 cue 的解析区间内；同一时刻、同一层的其他动作不算命中。未写目标的声明事件在对照中标未验证，但观察到的事件仍照常参与空档计算。积木块推出的事件自带卡片 ID 与行号。

### 4.7 Plan 减负

- **逐 Scene 一节**：
  - 一句场景概括。
  - A/B 编排：只写 A 与 B 各是什么、A → B → A 或 A → B、A 隐藏或虚化、延续自哪个 Scene；A-only 时写一行。
  - 积木块：`card` 块（第 4.4 节）；图解积木块待定（第 4.10 节）。
  - 事件表：每行 `cue | 层 | 目标 | 变化`，目标为卡片 ID、信息 ID、B 素材 ID 或元素 ID，可留空（留空时该行在对照中标未验证）；例外行写 `例外 | 起始 cue | 结束 cue | pause 或 talking_head | 原因`。只写积木块之外的事件。
