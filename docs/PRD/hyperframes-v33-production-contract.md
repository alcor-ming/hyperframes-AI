# HyperFrames v3.3 制作与工程合同

状态：已确认目标的 WSL 候选实现与规则整合；不是发行、部署或 Windows 原生验收声明。日期：2026-09-17。

本页是 v3.3 对原 v3.2 合同的当前增量。历史设计依据与决策台账不改写；运行状态以实际代码、检查与目标环境证据为准。

## 制作机制

制作入口为独立的叙事模式、视觉主题、背景与画幅，Motion 槽位可选或关闭；取消强制前置 Profile，不取消视觉一致性。2026-09-18 用户确认 Theme 与叙事模式分离：Theme 只拥有前景字体、颜色与卡片外观，不拥有背景、运动、mode、布局或 A/B；不再要求 Theme 声明双模式。Background 与 Motion 走同一资产接纳体系，Mode 属于制作输入，画幅与能力按组合验证。旧主题 ID 不自动等于合格新主题。IP Beta 可复用工程能力，但保留用户美术判断，不机械套标准模式。

四阶段顺序及接受真源为 [workflow](../../.studio/workflow.md)：内容准备、整片设计、Studio 制作与验收、Final 交付。Script 实质改写的条件确认保留；整片 Plan 与一个动态 Scene 一次方向确认；全片占位到素材齐备仅为准备度变化；最终接受准确 Studio Draft。PACKAGE 非视频前置，播客图文仍保持独立文章方案和包装合同。

表达要求只在 [visual-design](../../.studio/spec/visual-design.md) 维护：最小完整语义单元按对应短句/核心词实际起点快速出现，同卡旧文字位置/内容/可读性不变；长段可多 Scene，使用顺序推进、切出返回、同场叠层策略，任意 seek 重建同样状态。实际语义揭示与可见配图的停留期活动分别检查，不设每两秒动作配额，不提前揭完、不均分时间、不慢放简单动作填空。文字与图形互补，普通辅助图形由 Windows 制作者完成，不增加逐图审批；WSL 只维护工具和入口。主流程、Router、Recipe、主题参考不再各自编排完整流程。

## 工程控制面

系列聚合多期而不替代独立 Work 身份；显示改名不移动目录和依赖。Work 用途区分 standard、ip、test；生产 Variant 是账号版本，新建生产视频必须绑定已登记账号，测试 Variant 是测试批次且不绑定账号，可关联来源但不修改原作。AccountService 默认值及所选主题版本/参数复制到新建版本后固定，修改默认值不追改既有工程。未指定叙事模式默认 text-led，不自动填旧 Profile。所有新视频 Work 默认共享 Script/Research，各 Variant 的 Plan、工程、接受与 Final 独立，显式内容分支保留。

显式原位重绑定先展示差异再提交，保持同一 Variant 和历史文件，失效的新外观接受/Final 关联不得继承；中断须恢复一致状态，旧 runtime 仅在明确目标可编辑副本中受控升级。本地 Theme 字体经统一 load 等待后应用，实例隔离与清理，不静默回退。资产发现、MP3 media 与研究登记复用现有 CLI，查询/刷新/研究不修改已有 Work 或提升接受状态；精确命令与技术合同见 [hyperframes](../../.studio/spec/hyperframes.md)，不在本页维护第二份字段表。

软归档/恢复与制作状态正交：无 Final 可归档，不搬目录、不自动清理；查看不激活，继续制作保留旧接受/Final。旧 main、无系列、Profile 与物理归档保留读取，不批量历史迁移。

每个生产 Variant 独立 Finalize，编排必要镜头生成、正式渲染、编码 QA 和版本化交付，失败不覆盖旧 Final。接受来源、收据和文件保护继续保留，完成交付不自动归档。Draft、test-work 与测试路径禁止生成视频，Studio 受限不以短段/预渲染 MP4 绕过。Review 隔离不授予生产 Finalize。

快照与回收必须保护准确源、接受、Final、依赖引用、运行中任务和失败复现；避免无意义重复，不为省空间改成可变源硬链接，不在本次批量清理历史 Work。当前候选仅在 Finalize 成功后自动清理冗余 candidate；清理失败留记录，下次持锁 Finalize 核对当前 Final/manifest/candidate/QA 的 hash 与引用证明仍有效才重试。其他登记临时物须逐项通过范围、引用和进程检查，未登记 browser/build 缓存保留。

Finalize 记录真实 render/probe/decode 调用次数、耗时和返回码；工具内部重试、缓存命中、tokens 与成本未知时为 null，不把未取得数据写成零或节省证明。

## Remotion 与验证边界

HyperFrames 是唯一整片时钟及声音所有者，Remotion 接派生局部帧；ready、连续播放、暂停、seek/回拖、跨 Scene 和手机等效尺寸必须在 Windows 原生 Studio 验证。预览 JS 构建不是视频导出，不得离线编码或偷换 MP4。源、props、依赖锁和资源闭包可追溯；失败应冻结最小复现，不把独立 Player 或 mock 当 Studio 通过。

生产 Finalize 可在派生目录生成必要镜头媒体，绑定准确接受版本，不修改快照。全部相关输入不变才复用镜头；改动只失效影响部分。首次跨引擎输出须比较预览/Final 的语义帧、构图、字体、中文边缘、细线、透明合成、声音和时长。锁文件不是永久离线或跨 GPU 像素一致保证。

## 当前交付判定

- 既有 executable Studio Draft、准确接受、隔离审阅副本和 Final 收据继续保留。
- 本轮规则文件落实单一归属、三项入口和语义时序；工程增量属于 WSL 候选，须以对应可运行检查证明，不能仅由文档宣称完成。

## 规则归属

AGENTS 管环境与安全；Router 管对象/阶段定位；workflow 管四阶段及接受；creative 管来源/修订；visual-design 管表达/观看；hyperframes 技术规格管接线/编码 QA；Recipe 仅管人物结构差异；旧 Profile pack 仅可选外观参考。阶段按需加载，已有同版本、同对象有效检查复用，变更才检查影响范围；Studio、编码与归档完整性分别检查不同对象。
