# HyperFrames v3.6 showcase 模式、技术提炼与数学系列正式链路

日期：2026-09-29

状态：2026-09-29 按批准的审查补充并行实现 A（showcase）与 B（math-chain），开发源码已落地；WSL 自动化验收记录在两个 Trellis 任务中。C（math-kit）未启动；未部署、未提交，Windows 原生互操作及生产效果尚未验证。

版本归属：承接 [v3.5 有声动态图解](./hyperframes-v35-expression.md) 与 [v3.5.2 积木化资产库](./hyperframes-v352-asset-kits.md)。v3.5 D3 留给 v3.6 的 PDoom 路线在本版本以 `showcase` 模式的子模块落地；v3.5.2 第 4.10 节延后的图解积木，在本版本以数学图解积木为首批，并与 showcase 提炼共用 K1 原则。

来源：2026-09-29 对话中的产品线说明与决策；Work042、Work046 的 Claude 只读咨询结论（历史会话，未读取生产 Work）。

## 1. 产品线

| 线 | 模式 | 定位 | 制作模型 |
|---|---|---|---|
| 卡片 | `card` | AI 通识科普，矩阵账号，简单明了 | Codex / DS Flash |
| explainer | `explainer` | 本人 IP 账号系列，高成本，动效 + AI 生图，含教程 | Codex / DS Flash |
| showcase | `showcase`（新增） | PDoom 与炫技动效科普；当前为测试线，追近期热点，探索审美与动效结合 | 仅 Opus 5.5 |
| 数学思维 | 见第 4.4 节 | 从属系列，重制他人原片，说唱 + 知识，观众为零基础；当前为测试账号 | Codex / DS Flash |

showcase 线的首要价值是技术积累：把 Opus 的做法提炼成其他三条线的模型能直接使用的积木与配方，同时探索它自身作为长期科普形式的可能。

## 2. 目标

1. 新增轻量 `showcase` 模式，下辖 `pdoom` 与 `science` 两个子模块；只保留硬约束，不施加 explainer 的正向方向、Plan 字段与活力自检。
2. WSL 中的 Claude Code（Opus 5.5）能以生产执行者身份在 `D:\AI\AI+hyperframes` 制作 showcase 作品，与开发仓会话的职责明确分开。
3. 建立"提炼复盘"：showcase 成片接受后，把可复用做法整理成积木、配方或内容资产，供 Codex / DS Flash 使用。
4. 数学思维系列有正式链路：系列定义、原片声音的使用边界、说唱节拍时间依据、数学专项 Plan 字段、数学图解积木首批与审查包。
5. 事实、交付、工程正确性与授权四类硬约束不变。

## 3. 已定决策

- `V1`：版本定为 v3.6，三条工作并行推进（第 5 节）。
- `S1`：新设 `showcase` 叙事模式，轻量化，不做过多束缚；下辖 `pdoom` 与 `science` 两个子模块。
- `S2`：showcase 作品只由 Opus 5.5 制作。
- `S3`：Claude Code 只在 WSL 中使用，不在 Windows 安装或配置 Claude Code。
- `S4`：Opus 生产会话在 WSL 中直接操作生产根 `/mnt/d/AI/AI+hyperframes`，通过 Windows 互操作调用 `work.cmd`；作品、Draft 与 Final 仍在唯一 WorkStore，预览与渲染仍用 Windows 官方 Studio 与已部署运行时。
- `S5`：交给其他产品线的提炼成果必须是积木、配方、接口卡或 Plan 数据块，不直接交付 Opus 的整页代码。
- `M1`：数学系列当前沿用原片声音，处于测试账号阶段；有流量后进入重新制作。正式发布时的音频由用户自行处理，工具不做拦截。
- `M2`：数学系列使用 `explainer` 模式加系列规格 `math-rap`。
- `Q1`：v3.6 不做隔离候选根验证。部署在用户授权且没有并行 Work 进行时直接更新生产根，Windows 原生验证在生产根上完成；生产根上的效果试验使用 `purpose=test` 的 Work，不改既有作品。

## 4. 需求

### 4.1 showcase 模式

- 叙事模式增加 `showcase`：`MODES`、resolver、lock 校验、系列绑定与 CLI `--mode` 同步扩展。子模块 `pdoom` / `science` 写入外观 lock，创建时必须显式指定，冻结后不可改。
- 子模块只决定加载哪一份参考说明，不改变硬约束。
- 适用的硬约束：事实与来源可追溯、不伪造界面与数据；单一 paused timeline、seek 安全、状态不依赖 `onUpdate`；依赖与媒体离线闭包，不从 CDN 加载；授权边界与 Asset Brief 授权方式不变；Draft 不导出视频，只有生产 Variant 的 Finalize 渲染 MP4。
- 不适用：explainer 的正向方向与 Plan 字段、D14 主载体要求、Q1 活力自检、卡片形式规则、v3.5.2 节奏诊断的 Draft 前必经闭环（诊断可用，不强制处理）。五层结构、字幕、声音层为可选参考。
- Plan 模板为精简版：一句话概念、子模块、Scene 列表与各自要点、素材与声音清单、未验证项。元信息登记作者模型（审计用，不作门禁）。
- `pdoom` 子模块的代码绘制角色与表演在 Work-local 编写，Harness 不预建角色宿主或表演词汇；跨期复用的角色经提炼后冻结为 AssetSource 模块。
- 画幅：16:9 为主、9:16 为辅，同 explainer。

### 4.2 WSL 生产会话

- 生产根新增受管理文件 `CLAUDE.md`：声明本目录下的 Claude Code 会话是生产执行者，只接 showcase 作品的制作，以及数学等系列的只读审查（第 4.4.6 节）；引用根 `AGENTS.md` 的授权边界，不复制正文。
- 生产根新增受管理包装器（暂名 `work-wsl.sh`）：在 WSL 中把参数与路径经 `wslpath` 转换后调用同根 `work.cmd`，原样传递 stdout、stderr 与退出码；拒绝生产根之外的路径。这与现有 `asr-wsl.cmd` 方向相反、约束相同。
- 根规则修订：`AGENTS.md` 中"WSL 不修改生产 Work"改为按会话工作目录区分——开发仓会话（`/home/jym/workspace/hyperframes+AI`）继续遵守开发边界；生产根会话只通过包装器操作 showcase Work。同一 Work/Variant 同时只允许一个执行者的规则不变。
- Codex 规则写明不接 `showcase` 模式的制作。
- Opus 查看画面使用 CLI 生成的截图或诊断文件，不在 WSL 另起 Studio 或渲染器。

### 4.3 提炼复盘

- showcase Variant 被接受后，由制作会话按模板写一份提炼记录（新增模板，满足 T2"不产出模板外文件"）。逐项归为四类：积木（附接口草案与参数）、动作配方或规则、内容资产（签名音、背景、角色）、只属于本片。
- 积木与内容资产类条目：从 Work 中复制最小源码到 `asset-library/sources` 下新的可编辑源，不引用 Work 路径；之后走现有 pack / validate / accept。WSL 开发仓不读取生产 Work，需要工具改动时沿用"冻结最小复现交 WSL"。
- 规则类条目：作为开发仓的规则修订提案，按普通任务处理。
- 模板格式在第一期 showcase 成片完成前只定最小字段，第一期复盘后再修订。

### 4.4 数学思维系列

#### 4.4.1 系列定义

- 登记为生产系列（`purpose=standard`），不用 `purpose=test`（test-work 不能出片）。
- 模式为 `explainer` 加系列规格 `math-rap`（M2）：主载体改为数学图解，不要求角色与生图（覆盖 D14）；字幕层显示说唱歌词。

#### 4.4.2 原片与声音

- 原片经现有 `trendradar-media` 适配器进入 `materials/source-video.*`；正式声音取自原片音轨（M1）。
- Research 记录原片出处、原作者、所用片段，以及声音来自原片这一事实，供用户在正式发布前自行处理（M1）；工具不检查账号或声音来源。
- 原片画面只作结构参考，不复制进工程。

#### 4.4.3 时间依据

- 歌词逐字对齐：以人工校对的歌词文本为 Script，共享 ASR 结果按字符对齐；说唱 ASR 误差大，未对齐的字明确报告，不插值。
- 节拍网格：从正式声音提取拍点与小节，作为 cue 的第二来源；数学单元的揭示落在词上，重音与切换落在拍上。优先评估上游 `hyperframes beats` 在锁定版本中是否可用，不可用时再定实现。
- cue 助手扩展为可按"第几小节第几拍"取时间。
- 锁定 0.8.27 的包内 `beats` 文档与实现已核查：输出拍点、不输出拍号/小节。`beats build` 用隔离临时工程中的正式音频副本调用该命令，将显式拍号与首强拍索引合并到 `runtime/cues.json`；不更改生产工程的音频角色，不下载浏览器，不升级版本。真实 Windows 音频提取效果另验。

#### 4.4.4 数学专项 Plan 字段

仅在 `math-rap` 系列启用：

- 每个 cue 行写明保留、揭示、移除的数学单元。
- 符号表：每个符号在画面上的形象（面积、长度、单位块、份数、未知数方块），同一未知数全片同一形象。
- 不变量：如等号位置固定、公式行固定槽位不居中重排、"块内是这一块的值，块外是份数或总量"。
- 零基础核对：每个关系能否不借助代数知识从画面看懂；不能的写明由哪个画面动作承担。
- Plan 检查报告缺少图形职责的数学单元（Work042 的根因）与收尾超过 2 秒无事件的区间（Work046）。

#### 4.4.5 数学图解积木（图解积木首批）

- 沿用 K1：Plan 中的 `math` 数据块为唯一真源，CLI 生成挂载代码，事件由块中 cue 推出，模型不手写积木 HTML。
- 首批：固定槽位公式行；绘制的未知数方块（不用字体字符）；单位块与线段模型（含份数与总量标注）；面积正方形；数轴；删除线与否定；边的复制与飞入；等号的保持与迁移。
- 数学符号与中文标签使用冻结字体并声明字形范围，缺字形时构建失败，不回退系统字体。
- 符合现有合同：五层归属（图形第 2 层，独立文字第 4 层）、16:9 与 9:16、Theme token、seek 安全、节奏事件自动登记、快照闭包。

#### 4.4.6 审查包

- 新增 CLI 命令生成审查包：Plan、指定 Scene 源码、指定时刻截图、原片联系表、歌词字级时间与节拍；输出到 Review 范围，不含生产 Work 之外的内容。
- 实现入口为 `review package <id> --manifest <Work-relative JSON>`；截图与联系表先由既有工具生成，再按声明收集，不把用户声明的截图时刻冒充工具核验结果。包记录文件摘要，不自动导出视频。
- 审查由 WSL 生产根的 Opus 会话只读执行；输出格式固定：证据分【图】【码】【未实现】，严重度表，推荐分镜表。审查不修改 Work，也不代替用户观看。

## 5. 实施拆分

2026-09-29 审查补充：本轮只执行 A、B，C 不启动。A、B 的共享 CLI、系列配置、Plan 集成与规则由同一协调者写入，独立模块并行，整合后统一验证。`math-rap` 采用时校验最终模式与歌词字幕，并将系列身份、版本与规格冻结到 Variant；更新系列不追溯改变旧 Variant。既有 Variant 通过新采用的 Variant 使用新规格，不静默迁移。showcase 仅豁免表现形式检查，不豁免闭包与工程安全检查。

节拍网格绑定正式音频摘要，显式给出每小节拍数和首个强拍索引；弱起不默认算作第一小节。小节和拍从 1 编号，未确定、无效或越界查询报错；Python 与浏览器 cue 使用相同夹具验证。锁定版本无法提取时报告限制，不擅自升级或自制提取器。

## 6. 验收

**任务 A**

1. `work new` / `variant add` 可用 `--mode showcase --submodule pdoom|science` 冻结 lock；缺子模块、未知子模块、4:3 分别被拒绝；旧 lock 与既有模式的校验结果不变。
2. showcase 工程不触发 explainer 专项检查与 Draft 前节奏闭环；硬约束检查照常生效（CDN 引用、闭包外资产、`onUpdate` 写状态在夹具中被报告）。
3. `work-wsl.sh` 在 WSL 中调用 `work.cmd` 的结果与 Windows 直接调用一致（stdout、stderr、退出码）；生产根外路径被拒绝。Windows 原生互操作验证在部署到生产根后（Q1）单独报告。
4. 规则测试覆盖：生产根 `CLAUDE.md` 存在且引用授权边界；`AGENTS.md` 按会话目录区分开发与生产边界；Codex 规则不接 showcase；提炼记录模板存在。

**任务 B**

5. `math-rap` 系列的 Plan 缺少图形职责、符号形象不一致、收尾空档分别被报告。
6. 歌词对齐夹具中未对齐字符明确报告；节拍网格可按小节与拍返回时间。
7. Research 模板在 `math-rap` 系列中包含原片出处与声音来源字段。
8. 审查包只含声明的文件，路径不越出 Review 范围。

**任务 C**

9. 各数学积木在 16:9 与 9:16 下顺播、直接 seek、回拖一致；缺字形时构建失败；节奏诊断识别积木事件；CLI 据 `math` 块生成的工程与 Plan 一致。
10. 效果验收（用户判断）：部署后在生产根新建一个 `purpose=test` 的 Work，用数学积木重做 Work046 的一个 Scene，用户在 Studio 中带声观看，判断零基础观众能否看懂。不导出视频。

**通用**

11. 全量隔离单元测试与 `validate_package.py` 通过；程序与规则、WSL 证据、Windows 原生证据与生产验收分别报告。

## 7. 不做

- 为 showcase 预建角色宿主、表演词汇或审美规则。
- 数学系列的自有音频重制（有流量后另行立项），以及任何账号或声音来源的工具拦截。
- 隔离候选根部署与验证（Q1）。
- explainer 的系列角色与生图规则改动；卡片模式迁移到五层结构。
- 升级 HyperFrames 锁定版本（若 `beats` 不可用，另议）。
- 部署、提交、读写生产 Work 或资产库（生产行为按各自授权进行）。
