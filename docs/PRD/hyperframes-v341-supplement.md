# HyperFrames v3.4.1 补充方案

日期：2026-09-23；WSL 采用日期：2026-09-24

状态：已在 WSL 开发源码落实。编号承接为“归档生产 Work 的继任作品承接原系列号”；取消“必须先有主账号”和 main 的特殊地位，保留 Variant 的账号归属与配置冻结。具体验证以本轮开发结果为准，不把源码实现或合成测试写成生产变更完成。

版本归属：HyperFrames v3.4.1，承接用户已完成的 v3.4 RC2。该名称是本次目标版本，不代表已生成 3.4.1 发行包，也不推断 v3.4.0 正式版是否发布。保留 RC2 已完成实现，不重跑旧身份迁移。

本文件语义采用用户指定的 Windows 创作根 `docs/PRD/hyperframes-v341-supplement.md`（2026-09-23 方案），不是两端自动同步。原件保留生产交接对象；本开发仓只保留产品合同和合成编号验收，不复制生产 Work 私有标题、媒体或内容。开发验证延续相关 WSL 单元/smoke 检查，不新增强制人工或 Windows Studio 验收。

## 1. 采用时的基线

原方案记录的安装行为如下，作为问题背景，不等于本轮重新审计生产安装或全部 RC2 历史：

- 已有独立系列号、高水位、旧 ID 别名、账号多 Variant 和名称化视频 Work ID；测试的 `series_number` 为空。静态检查不能冒充实际新建续号通过。
- `series_number()` 使用已保存高水位与当前已观察系列号的最大值加一，不能笼统称“没有续号机制”。
- 未见独立 Work 主账号字段。约束在创建路径：`command_new()` 先获取必须绑定账号的生产 Variant 设置，再固定创建 `main`，并把 Current Variant 指向它。
- `selected_variant()`、`command_use()` 和恢复入口优先 main，“main 只是普通 ID”的说明尚未彻底落实为无偏置选择。
- `WORK.template.md` 固定 `required_variants=["main"]`；完成判定读取该集合，不能只改显示名称。

## 2. 编号承接补齐

### 已确认业务场景

这不是普通新建续号故障，而是现有 append-only 分配器缺少“同一期内容的继任 Work”入口。原生产对象与准确接受版本仍以用户原交接为准，本仓不读取或复制该交接内容；创建前须核对实际快照和来源文件。此开发任务不执行真实继任。

合成验收使用系列 `fixture-series` 的 001、002、004，源 Variant 为 `main`，指定接受版本分别为 `draft-v003`、`draft-v003`、`draft-v002`，新制作账号均为 A。A 已确认，不再询问，但不拥有主账号地位。

旧 Work 保持归档只读，新的生产 Work 使用独立 ID，分别继续作为 001、002、004 的当前制作对象；不能悄悄新建为 016、017、018，也不能把旧 Work 直接 reopen 后修改。

### 语义：不是回收旧号，而是承接同一编号的制作关系

系列号表示该系列的一期内容；Work ID 表示一次独立生产实体。一个系列号可以保留旧归档实体和继任实体的历史链，但只有一个当前定位对象。普通无关 Work 仍不得使用已占用号。

源 Work 的 `series_number`、ID、账号、归档记录、冻结接受和 Final 全部保持原样。新 Work 记录相同系列号及准确的继任来源；同号是受工具校验的承接关系，不是放开任意重复编号。

### 最小工具合同

1. 提供显式“从指定归档 Work 创建继任 Work”的受支持入口。参数确定源 Work、源 Variant、源版本和新制作账号，不能仅接受裸数字覆盖任意对象。
2. 扩展现有 `work-identity.json` 或现有身份记录，保存当前定位目标与前后承接关系，不创建独立数据库。继任关系与普通素材 `source_work` 引用分开，引用旧素材不能抢占其系列号。
3. 源须为已归档且属于同一生产系列的准确对象。仅在它仍是该编号可承接的当前末端、没有另一继任占用时允许创建；拒绝环、分叉和无关同号。跨系列转移保留既有机制，不混入此次操作。
4. 新 Work 分配新全局内部 ID/目录；系列号保留原号，不提高也不降低系列高水位。普通新一期按原高水位顺延；测试和新增 Variant 不占生产系列号。
5. 从指定接受版本采用内容、媒体和来源关系到新 Work 自有位置，按新账号准确配置创建制作 Variant。保留来源证据，不继承旧接受权限、当前 Final 或完成状态；新作品重新进入正常制作过程。
6. 创建、关系登记与编号当前目标切换是可恢复的一次操作，使用现有锁、staging 和原子提交惯例。失败不留下半个继任或指向不存在的目录；重试识别同一已完成请求并返回准确对象，不创建同号分叉。
7. 按系列与编号查询定位新 Work，历史查询展示完整链。精确旧 Work ID 仍打开旧归档实体，已有旧 ID 别名继续指向原实体。
8. 当前生产列表只展示新对象，旧对象只在归档/历史区域。新对象以后归档或删除时，不自动恢复更旧对象为当前制作、不回收编号；留下历史占用或明确无活动对象，后续继任仍须显式发起。

### 对现有假设的必要调整

- “同系列同号绝不重复”收窄为“无承接关系的重复拒绝，同号只有一个当前定位目标”。列表扫描、find、迁移检查、导航、导出/恢复身份状态使用同一规则。
- 承接是一般修订或 Variant 之外的窄例外：原实体已归档、须只读，且明确要求新生产实体继续同一期编号。日常改字、账号适配仍优先使用已有活动 Work。
- 不重跑 RC2 身份迁移，不清零高水位、不重编号其他 Work、不批量改写归档元数据；历史缺失或冲突明确报出，不靠覆盖恢复。

### WSL 小规模验证

合成 fixture 保留 001-015，将 001、002、004 设为归档来源并创建继任：验证原号保留、新 ID 唯一、普通新一期仍为 016、旧源哈希不变、旧 ID 定位旧对象、系列号定位新对象、列表分区正确、无关重复拒绝、中断/重试不产生双继任、删除当前对象不回退占号。只要求相关单元与 smoke，不追加人工或 Windows 验收。

## 3. 已确认：取消主账号与 main 特殊地位

### 问题不是账号 A/B/C 有层级

层级来自“创建 Work 必须同时创建绑定账号的 main”及默认选择、默认交付集合。即使没有 `primary_account` 字段，第一个账号版本仍获得特殊地位。仅改 main 显示名不能解决必须先选账号、默认跳 main、main 隐式进入交付集合，不作为最终修复。

### 已批准方案

Work 是不属于任何账号的内容单元；所有 Variant 平级，账号只绑定对应 Variant。取消创建与选择中的多余主次关系，不清除账号字段、解除已有绑定或取消冻结快照，不新增 `primary_account`、`primary_variant` 等变相层级。

```text
系列 007 · 一项内容
  shared/                共享来源、Script、Research
  variants/
    B · 竖版完整版       账号 B，独立 Plan/工程/接受/Final
    C · 竖版完整版       账号 C，独立 Plan/工程/接受/Final
```

此图是关系示意，不要求迁移物理路径或把账号名称设为唯一 Variant ID。

- 创建 Work 可暂不指定账号、暂不创建 Variant，先整理共享来源和内容；没有账号不等于实验，正式用途和系列保持明确。
- 用户明确“给 B 做一期”时，可一次创建 Work 和 B Variant，不增加两步手工操作，也不称 B 为主账号。
- 同账号可有多个平级 Variant；首个版本不拥有其他版本，不天然作为其来源。
- 新版本默认使用 Work 共享来源；派生需显式指定源 Variant，不隐式继承 main 的 Plan、主题或账号设置。
- 新建生产 Variant 仍须绑定准确账号并冻结配置；旧未绑定 Variant 按既有历史兼容读取，不自动补绑。
- 保留 `account`、`account_revision`、`account_settings` 与 `appearance_lock` 职责。服务默认配置不热改已有 Variant；采用新版仍为显式修订，不影响旧接受与 Final。

### 选择与操作

- Work 级命令（内容整理、来源、列表、状态概览）不强制选 Variant；零 Variant 正常显示“尚未创建制作版本”。
- Variant 级制作命令优先本次显式选择，否则只能使用确属该 Work 的有效当前选择或唯一候选。
- 多候选且无准确选择时返回候选，不按 main、字母顺序、首个创建时间或账号优先级代选。
- Current 只是操作焦点，不是主账号、所有者或交付优先级；切换 Work 不沿用另一 Work 的当前版本。
- 无 Variant 不可执行需要工程的制作、预览、Finalize，但可继续 Work 级内容准备。

### 交付范围与历史兼容

- `required_variants` 若保留，只表示本期明确交付集合，不表示账号主次。
- 新 Work 的交付集合可尚未确定；零版本或空集合不得视为“全部完成”，避免空集合真值漏洞。
- 一个 Variant 的 Final 不自动代表 Work 全部完成；未明确交付范围时按版本报告，不猜整体完成。
- 旧 main、账号绑定、required_variants、历史接受和 Final 保持兼容，不批量重命名、删除或解绑，只移除新操作中的特殊优先级。
- 当前冻结配置仍有效，不因取消 main 偏置而改用服务最新版。
- `podcast_quote_image` 不随视频合同改变；同类需求独立讨论。

## 4. 最小实施面

两项设计均已明确，不再询问是否取消 main。合成 001、002、004 的 A 选择保留，一次创建继任与 A Variant 不赋予 A 主账号地位。

1. 分开 Work 内容容器与账号 Variant 创建；共享 Script/Research 不依赖先创建 main 再搬出文件。
2. 支持零 Variant 的元数据、Current、list/status/use；需要 Variant 的操作给出准确错误。
3. 清除选择、恢复、继承和模板中的 main 特权，交付集合独立处理。
4. 同步 Router 和新建提示：准备正式内容不强迫选账号，也不误分流到实验。
5. 更新 WSL fixture，验证平级多账号、零版本、旧 main 兼容和空集合不算完成；生产 Variant 仍要求账号，默认配置更新不改变已有冻结设置或接受快照。

本轮 CLI 合同：

```text
work new TITLE --workflow hyperframes_video --purpose standard --series SERIES
work new TITLE --workflow hyperframes_video --purpose standard --series SERIES --account B --variant-id ID
work successor SOURCE --source-variant ID --source-version draft-vNNN --account A [--variant-id ID] [--title TITLE] [--detached]
work find --series SERIES --number NUMBER [--history]
```

首行不创建 Variant；第二行一步创建 Work 与准确账号版本。创建 Variant 时省略 `--variant-id` 可沿用 `main` 这一普通兼容 ID，不授予选择、继承或交付特权。部署根是否具备命令须检查其实际帮助，文档采用不证明已安装。

继任的冻结 Script/Research 采用到 `shared/`；原工程、闭合媒体、原 Plan 和来源校验记录保存在新 Work 的 `materials/predecessor/`。新 Variant 冻结指定账号配置，使用新的 Plan/接受/Final 流程；不把旧账号的 Plan 或工程视作新账号已批准内容。缺失冻结文稿或依赖不闭合时拒绝，不从旧可编辑文件猜测接受内容。中断后重试原命令恢复；既有继任请求返回原对象，不再次分配编号。

不变更 Windows 安装目录，不执行真实作品继任或迁移，不自动升级账号配置。实施不包含安装、生产激活或 Git 写操作。
