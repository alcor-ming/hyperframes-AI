# F01–F08 卡片 SVG 槽设计要求

日期：2026-09-28

用途：交给 Windows 侧完成 [v3.5.2](./hyperframes-v352-asset-kits.md) 阶段二的视觉设计稿（决策 C7）。用户从设计稿中选定后，阶段三按本文的插槽合同实现卡片积木。本文只规定要设计什么、交付什么，不规定具体视觉；各预设的槽位建议仅供参考，由设计侧决定取舍。

## 1. 设计对象

Windows 资产库中已批准的 `card-family-source@v1`（F01–F08）。在其基础上派生新版本，不修改已批准的源码。八个预设的材质、结构与身份保持不变：

| 预设 | 名称 | 身份 |
|---|---|---|
| F01 | 白页标注 | 打开的纸页，每行由 cue 画出局部边注线 |
| F02 | 柔雾色块 | 标题 / 正文 / 脚注三个平面文本带 |
| F03 | 毛玻璃 | 半透明玻璃面，背后有可辨认的图形 |
| F04 | 索引档案 | 内容页 + 细索引脊，提供键时出现刻度 |
| F05 | 编辑引文 | 标题 + 缩进 / 偏移的段落组 |
| F06 | 票据清单 | 台账：表头横线、行轴与结尾区，可为键值 |
| F07 | 窗口面板 | 开放文本工作面，可有输入 → 输出关系 |
| F08 | 硬边叠纸 | 前层阅读面 + 错位后层纸边 |

## 2. 已定前提

- 卡片是画面中的一块，同一 Scene 可以放多张，并与图解、B-roll 同框（C2）。
- 条数可变；容量超限时报溢出，不缩字、不截断（C3）。
- SVG 槽接受图标集中的图标（首个为 Lucide，单色线性、`currentColor`）与本片自制的示意 SVG（C4）。
- 动作由卡片自带，模型只提供每行的 cue（C5）。SVG 随所在行或所在区域的 cue 出现。
- 文字在第 4 层；卡面、装饰与 SVG 槽在第 2 层，二者由同一布局对齐。
- 外观随 Harness Theme token 变化；卡片不再自带 light / dark 与背景选项。设计稿至少在一套浅色与一套深色 Theme 下呈现。
- 只做 16:9 与 9:16，不做 4:3。
- 没有提供 SVG 时，槽不留空洞，版面按"内容优先"收拢。

## 3. 设计要回答的问题

每个预设都需要明确：

1. **有哪些 SVG 槽**。建议从三类通用槽中选择，也可以提出预设专有的槽：
   - `title`：标题旁的图标位，每张卡最多一个。
   - `line`：条目行旁的图标位，每行最多一个，可以只给部分行。
   - `figure`：较大的示意图区，承载自制示意 SVG 或放大的图标，每张卡最多一个。
2. **每个槽的位置与尺寸**：在各区域（见第 4 节）下的设计像素尺寸、对齐方式，以及紧凑布局（卡片宽度小于 1000 设计像素）时如何重排。
3. **有无 SVG 时的版面差异**：提供与不提供时正文宽度、行高、留白如何变化；不得因为有 SVG 而缩小字号。
4. **SVG 的出现与强调**：随所在行 cue 出现时的动作；当前行强调时 SVG 是否一起强调；退场方式。
5. **容量**：各区域下，有 SVG 与无 SVG 时的最大条数与每行大致字数。
6. **自制示意 SVG 的约束**：`figure` 槽能接受的长宽比、线宽与配色约定（使用 Theme token），以免与卡面风格冲突。

## 4. 区域与尺寸（设计工作假设）

区域名由 16:9 与 9:16 各自映射到实际分配尺寸（C8）。设计时按下表假设，最终数值在阶段三实现时确定：

| 画幅 | 区域 | 设计尺寸（约） |
|---|---|---|
| 16:9 | `full` | 1776 × 936 |
| 16:9 | `left` / `right` | 864 × 936 |
| 9:16 | `full` | 936 × 1776 |
| 9:16 | `top` / `bottom` | 936 × 864 |

9:16 下原工作台采用左右双栏（444 × 1776），较窄；设计稿中请评估是否改用上下分区，或保留窄栏作为额外区域。

## 5. 各预设槽位建议（仅供参考）

| 预设 | 建议 |
|---|---|
| F01 白页标注 | `title`；`line` 放在边注线一侧，与边注线同时出现；可选页角 `figure` |
| F02 柔雾色块 | `title` 在标题带；正文带侧边 `figure`；脚注带小图标 |
| F03 毛玻璃 | 玻璃后的图形位改为可替换的 `figure`（不占前景阅读宽度）；`title` |
| F04 索引档案 | 索引脊上的键位可放图标，与键文字并存或替代刻度；`title` |
| F05 编辑引文 | 克制使用：可选侧栏 `figure`；一般不加 `line` |
| F06 票据清单 | `line` 放在键列；表头 `title` |
| F07 窗口面板 | 输入区、输出区各一个图标位，关系处可放示意；`title` |
| F08 硬边叠纸 | 前层 `title` 与 `line`；后层层名旁可放图标 |

## 6. 交付物

1. **可交互预览页**：沿用原工作台形式，可以切换预设、画幅、区域、Theme（浅 / 深）、条数（2、4、6 条），以及是否提供 SVG（无 / 仅 `title` / `title` + 部分 `line` / 含 `figure`），并支持拖动时间轴查看逐行出现、强调与退场。
2. **每个预设一张槽位规格表**：槽名、适用区域、各区域下的尺寸与对齐、紧凑布局下的位置、容量（有 / 无 SVG）、接受的内容（图标 / 自制示意）、出现与强调方式。
3. **示例内容**：用 MCP 主题的真实文字与 Lucide 图标填充，另附至少一个 `figure` 槽的自制示意 SVG，避免只用占位文字评审。
4. **变更说明**：相对 `card-family-source@v1` 改了什么，哪些预设的身份受影响。

设计稿作为新的可编辑源放在 Windows 资产库，不覆盖已批准版本。

阶段二的验收条目见 v3.5.2 PRD 第 6 节第 14–16 项。

## 7. 选定之后

- 用户从预览中选定每个预设的槽位方案；未选定的预设可以暂缓，不阻塞其他预设。
- 选定方案写入阶段三的插槽合同，并补充 `card` 块中各预设专有槽的写法。
- 阶段三补做浏览器与 Windows 原生 Studio 验证；设计稿阶段只需要浏览器预览。
