# Template A — Talking-head Enhancement

## 定义

存在必须保留为主体的原始人物口播视频：

```text
原人物视频 = 主视觉
HyperFrames = 解释、强调与结构化信息层
```

## 输入

### 必需

- 原视频文件。

### 可选内容来源

- 原视频转录；
- 字幕文件；
- 口播稿；
- `资料.md`；
- `section_map.json`；
- 产品图、Logo、截图、图片。

没有转录或 `section_map.json` 时，允许从视频音轨分析内容。

## 时间轴

默认：

```yaml
timing: source_locked
voiceover: source
```

用户指定替换音频时可改为 `audio_locked`。

## Scene 类型

- `quiet_hold`：不增加新视觉信息，让人物和口播独立成立。
- `keyword_anchor`：关键词、术语、产品名或数字。
- `explainer_overlay`：一句解释、示例或状态变化。
- `relation_trace`：因果、输入输出、依赖或路径。
- `step_sequence`：2–5 个步骤逐步推进。
- `data_punch`：关键数字、比例或变化。
- `comparison_overlay`：A/B、前后、问题/方案。
- `product_callout`：产品图、Logo、对象说明。
- `full_frame_insert`：短暂全屏解释；属于例外，必须在计划中明确。

Scene 类型不是必须写进用户可见表格，但可作为实现元数据。

## 视觉权重

默认同一时刻：

```text
1 个主信息 + 1 个辅助信息
```

普通叠加层视觉权重约占画面 15%–30%。复杂解释可提高，但不应默认覆盖人物。

## Hero State

每个 Scene 必须先判断：

- 人物位置；
- 人脸保护区域；
- 已有字幕保护区域；
- 可用负空间；
- 叠加元素完成入场后的稳定构图。

人脸区域禁止文字、图标、面板和背景模糊。冲突时优先重排，不通过降低文字不透明度解决。

## 节奏

宏观信息组通常持续 6–14 秒，但应以语义为准。组内允许微强调，不能让画面持续处于多元素运动状态。

`quiet_hold` 是正式场景，不是缺少设计。

## 图片资产

适合生成：

- 抽象概念隐喻；
- 未来产品或不存在的场景；
- 短暂章节插图；
- 缺乏现有素材时的辅助视觉。

不适合生成：精确 UI、Logo、数据图、流程图、中文文字或真实证据截图。

## 字幕

原视频已有清晰字幕时，将其视为保护区，不重复生成。需要字幕时，把它作为当前模板的组件加入，而不是切换模板。
