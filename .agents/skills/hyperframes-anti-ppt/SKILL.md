# HyperFrames 信息型动效

## 职责与边界

目标是带声连续观看时观点易懂、手机等效尺寸清晰、视觉不过度疲劳，不要求静音复述全部论证。动画型检查对象识别、比较或过程；文字型检查卡片阅读、装饰、关键词强调与声画分工。主类型与 A/B 默认区间依 `.studio/workflow.md`，独立于 Template/Profile，不强迫每场机制演绎。名称保留兼容既有路由。

输入是当前 Scene 的 Script Anchor、Research 研究条目及必要资料依据、时间依据、Recipe、Profile、画幅、Plan 与实际样段或 Draft；只读取必要衔接。不得擅改口播、时间权威、已批准语义或其他 Scene。不修改 HTML、CSS、GSAP、Three.js、音频或字幕；主视频工作流负责等义适配和实现。

结果合并进现有 `ANIMATION_PLAN.md` 或 Draft QA，不新增 Motion Plan、Shotbook、Scene 数据库或审批。先整片 Plan，再一个真实 Scene 动态参考，一次方向批准后扩成完整 planned-placeholder Draft，素材齐备后按原流程接受最终 Draft。组件检索、版本、Binding 和安装仍属于视频工作流。

## 先看信息，再看运动

核心内容以 Script 与已批准 Plan 为准；Research 是可选用的视觉内容与素材，不把候选“核心”标记当作必上屏义务。Plan 可自主取舍研究材料，审阅不以研究文字是否全部出现为标准。

按 `.studio/workflow.md` 筛选有效信息，允许不上屏的铺垫、情绪、衔接和同义重复，不遗漏改变结论的条件，不重复内部归属提示。Plan 记录实际采用的屏幕文字、来源与声画取舍，不复制完整 Script/Research，不为每句口播另写同义稿。逐字引用关联 Anchor，独立信息关联 Research，素材内原生文字归素材。内容过多先调整分组、时序、布局或等义措辞，不能兼顾确认结论与原时长时才提出局部取舍。

文字可负责精确解释，素材可直接承载原生信息，不要求再覆盖同义文字。SVG、icon 和图片允许主要承担装饰价值；文字型大部分卡片有装饰，允许短暂纯文字，避免细碎点缀增加扫描负担。关键词用下划线/加框等局部强调，不默认逐字跳动或整段移动。Three.js 仅用于需要的空间关系，不靠删核心信息、无限缩字或正文漂移制造“反 PPT”。

按当前内容选择表现，不强制 Hero 动词、不可逆变化、固定 Beat 数或统一入场：

| 信息需求 | 可采用的表达 | 需要保护的内容 |
|---|---|---|
| 对比工具的适用边界 | 稳定对比表，迁移焦点，局部展开当前差异 | 并列关系不能硬接成必经工作流 |
| 输入、处理与输出 | 保持对象身份，逐步改变内容并标出规则 | 输入条件、真实动作、结果与限制 |
| 解释概念与条件 | 正文按含义分组，图形关联到具体术语 | 完整解释不能只剩关键词 |
| 查看真实操作证据 | 放大相关区域，稳定注释，再回到上下文 | 不以模拟 UI 冒充真实产品能力 |
| 聚合、筛选或空间分层 | 可追踪对象与对应说明同步变化 | 为什么保留、排除或分层，不能只看见随机运动 |

标题、段落、列表、截图、卡片、对比表、箭头及稳定阅读都可以成立。静态关键帧能表达完整信息不是失败；不要求去掉文字仍能理解全部机制，也不把依赖容器组织信息作为自动重写理由。

## 阅读与隐喻

每组必要文字应在真实速度、实际显示尺寸下有稳定阅读窗口。可保留已讲内容作为上下文，下一组出现时明确焦点。复杂正文进入时降低其他区域运动；观察空间变化时说明文字可稳定留存，不必全画面静止。

保留原口播和原总时长，整幅画面连续完全静止不得超过2秒，正文及单个对象可稳定停留。先分配内容和 A/B 时间，再逐步呈现、关键词强调、稳定阅读，必要时少量图标轻动/框线绘制/图片缓推。不前几秒揭完后等声音，不填文字凑时间、不剪口播、不默认加 BGM/SFX，不用反复闪烁或无限装饰循环规避。实际播放人工核验可感知变化和阅读干扰，不以 tween 存在或数量判定通过；自动容差待 Windows 实测。

不设所有 Scene 通用的字数、字体、文字占比、停留时长或结尾 `0.4s` 规则。遮挡、越界、正文漂移或被景深模糊是具体问题，不是要求所有场景采用同一布局的理由。

关键隐喻用一句话交代对象代表什么、动作映射什么关系、观众应得出什么结论。并列、比较与因果不能偷换。真实证据、模拟操作、概念示意要可区分；数字、排名、成功状态与百分比应有依据或标为演示值，没有可定义进度时不用 `0 -> 100%`。

## 预演与局部复审

Plan 检查全片 A/B 叙事职责、语义对象、内容/媒体引用、阅读与 cue 意图；随后只审一个真实 Scene 的动态参考，优先复用已有成果。实际可见关系、运动和文字可读，未展示 Scene、临时音频及占位明确未验证。全片配色/字体可共享，参考的局部布局不自动推广全片；不得以旧零样段或静态检查代替本轮动态方向参考。

Draft 默认在官方 Studio 检查实际关系、运动、阅读、素材与交接，无需先导出整片 MP4。素材齐备后注册 Studio Draft，再打开准确 draft-id 的隔离副本审阅、接受。动画型检查必要对象/关系/结果，文字型检查卡片阅读/装饰/关键词强调，不将文字卡片自动判为缺陷；只看开头或 contact sheet 不足以动态通过。检查实际声音、连续播放、跳转/回拖；局部播放受限可导出带声短段，不静默恢复整片 Draft 导出。未听音或缺 Windows 证据明确未验证。

已接受且未变只核对来源和证据适用性；局部变化检查受影响状态及交接，共享布局/时间线/宿主变化按依赖扩展。新 Final 编码检查流、规格、时长、全量解码、代表帧及必要音频，不重复已接受设计审批。Finalize/归档只核对来源、render 记录、文件、目标与归档结果，不再次审片或重渲染。

反馈定位到版本、Scene、必要时间范围或对象；先保留用户明确要求不变的内容与视觉，再提出最小有意义修改并检查受影响衔接。换行、分组、顺序、表现标签和等义精简交由主工作流原位处理；删除核心信息或改变事实、观点、因果及已确认叙事才报告真实取舍。主构图或视觉目标实质变化只回到该部分确认。

复用优先选有意义且内部联动完整的视觉对象，由 Scene 安排当前叙事；既有 helper 不强制合并或拆解，不设五阶段、双画幅、透明根层或复用比例。图标/图片可为主体或证据，空间舞台保持内聚。Windows 开发视觉内容，只有真实工具/宿主缺口交 WSL；保留已有 M2–M3 画面与冻结历史，两次技术绑定不等于真实生产复用。

## 输出

只报告具体结果和必要修改：Scene / 时间范围、必须保留的结论、观察到的问题、建议的文字 / 素材 / 动作职责与阅读安排、受影响衔接、未验证项和真实取舍。复杂场景可用时间表，不要求每场完整套表或拒绝清单。

`PASS` 只说明当前证据未发现必须修复问题，不代表方向批准或整片接受。完整占位 Draft 允许已登记 planned placeholders、临时音轨和已约定 proxy；计划内缺素材不能按旧规则阻塞全片预览。空 Scene、代码错误、缺失观点和虚称已实现动作须修复。最终 Draft/Final 才要求必需媒体、最终音频和效果齐备。未听音、缺动态或 Windows 原生证据时明确未验证。
