# HyperFrames 信息型动效

## 职责与边界

目标是保留精确信息，用动效帮助观众理解，而不是减少文字、增加动画或让每场套用统一公式。名称保留兼容既有路由。

输入是当前 Scene 的 Script Anchor、Research 采用信息及必要资料依据、时间依据、Recipe、Profile、画幅、Plan 与实际样段或 Draft；只读取必要衔接。不得擅改口播、时间权威、已批准语义或其他 Scene。不修改 HTML、CSS、GSAP、Three.js、音频或字幕；主视频工作流负责等义适配和实现。

结果合并进现有 `ANIMATION_PLAN.md` 或 Draft QA，不新增 Motion Plan、Scene 数据库或审批。Plan 先逐 Scene 匹配已接纳资产，仅为真实设计缺口制作静态样段，数量可为零；组件检索、版本、绑定和安装仍属于视频工作流。

## 先看信息，再看运动

先按 `.studio/workflow.md` 筛选有效信息、删除无增量重复并排除制作说明，再明确结论及不可遗漏的术语、条件、步骤、例子与证据。检查它们是否由文字、素材、操作或动效正确表达；可选说明为空无需补齐。逐字口播引用 Script Anchor，独立信息引用 Research 采用条目，素材内原生文字归素材，表现标签归工程；Plan 不手工复制信息稿或标签清单。信息过多先调整分组、时序、布局或等义措辞，确实无法保留核心信息与时间预算才提出局部取舍。

文字可负责精确解释，素材可直接承载清楚的原生信息，操作或动效可展示过程与关系；不要求再覆盖同义文字。GSAP 负责阅读顺序、重点迁移、关系、证据放大和对象连续性；Three.js 仅用于确有价值的空间层级、路径、聚合或遮挡。不能靠删核心信息、无限缩字、让正文一直运动或装饰粒子制造“反 PPT”。

按当前内容选择表现，不强制 Hero 动词、不可逆变化、固定 Beat 数或统一入场：

| 信息需求 | 可采用的表达 | 需要保护的内容 |
|---|---|---|
| 对比工具的适用边界 | 稳定对比表，迁移焦点，局部展开当前差异 | 并列关系不能硬接成必经工作流 |
| 输入、处理与输出 | 保持对象身份，逐步改变内容并标出规则 | 输入条件、真实动作、结果与限制 |
| 解释概念与条件 | 正文按含义分组，图形关联到具体术语 | 完整解释不能只剩关键词 |
| 查看真实操作证据 | 放大相关区域，稳定注释，再回到上下文 | 不以模拟 UI 冒充真实产品能力 |
| 聚合、筛选或空间分层 | 可追踪对象与对应说明同步变化 | 为什么保留、排除或分层，不能只看见随机运动 |

标题、段落、列表、截图、卡片、对比表、箭头及稳定阅读都可以成立。静态关键帧能表达完整信息不是失败；不要求去掉文字仍能理解全部机制，也不把依赖容器组织信息作为自动重写理由。

## 阅读与隐喻

每组必要文字应在真实速度、实际显示尺寸下有稳定阅读窗口。可保留已讲内容作为上下文，下一组出现时明确焦点。复杂正文进入时降低其他区域运动；观察空间变化时说明文字可稳定留存，不必全画面静止。

不设所有 Scene 通用的字数、字体、文字占比、停留时长或结尾 `0.4s` 规则。遮挡、越界、正文漂移或被景深模糊是具体问题，不是要求所有场景采用同一布局的理由。

关键隐喻用一句话交代对象代表什么、动作映射什么关系、观众应得出什么结论。并列、比较与因果不能偷换。真实证据、模拟操作、概念示意要可区分；数字、排名、成功状态与百分比应有依据或标为演示值，没有可定义进度时不用 `0 -> 100%`。

## 预演与局部复审

Plan 检查逐 Scene 方案、已验收资产适配与必要缺口样段：关系、真实文字、素材、画幅、时间与状态变化均匹配合同，不能只凭名字或截图选组件。全部适配可零样段；同类缺口验证一次并列明适用 Scene 与差异。样段需要阅读的文字完整可读，画幅、颜色、字体和层级可判断，主要动作写清对象关系、起止状态与阅读安排。全片配色 / 字体可共享，局部布局不自动覆盖其他 Scene。媒体可语义占位，未实现动作明确未验证；静态样段不因缺动画失败，不要求全片可播放，够判断当前缺口即停止。

Draft 默认在官方 Studio 检查实际关系、运动过程、阅读窗口、素材和交接，登记版本只看隔离副本。问题 Scene 至少检查稳定状态与核心变化：连接有指向、分支有条件和去向、反馈改变状态；只看开头或 contact sheet 不足以通过。字段留在 JSON 或统一排成文字行不等于关系实现，未支持表达应报告局部缺口。相似外观、共用 easing 或入场函数不自动失败；不强求各 Scene 视觉不同。完整 Draft 与 Final 仍要求必需内容、效果和媒体就绪。新效果默认在 Draft 内最先验证，只有改变整体决策的风险才提前局部试做。

反馈定位到版本、Scene、必要时间范围或对象；先保留用户明确要求不变的内容与视觉，再提出最小有意义修改并检查受影响衔接。换行、分组、顺序、表现标签和等义精简交由主工作流原位处理；删除核心信息或改变事实、观点、因果及已确认叙事才报告真实取舍。主构图或视觉目标实质变化只回到该部分确认。

复用区分完整叙事组件、动作/效果模块与参考经验。候选须适合真实文字长度、信息形态、画幅、时长与素材；默认一个推荐，仅存在实质取舍时比较备选。不预设整库目录或强制复用比例，不删除未来设计；改组件内部实现应派生 Work-local custom，不覆盖冻结 vendor。两次技术绑定不等于两次真实生产复用。

## 输出

只报告具体结果和必要修改：Scene / 时间范围、必须保留的结论、观察到的问题、建议的文字 / 素材 / 动作职责与阅读安排、受影响衔接、未验证项和真实取舍。复杂场景可用时间表，不要求每场完整套表或拒绝清单。

`PASS` 仅表示当前阶段可见证据未发现必须修复的问题，静态 Plan 的 `PASS` 不证明动效通过，也不代表用户已接受 Draft。`REWRITE` 用于缺字、错误关系、遮挡、无法阅读，或完整 Draft 缺必需效果等实际问题；Plan 计划中的未实现动作不是失败。审美建议与必须修复项分开，不为追求 `PASS` 循环重构；缺动态证据明确未验证。
