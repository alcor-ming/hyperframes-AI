# HyperFrames 信息型动效

## 职责与边界

目标是保留精确信息，用动效帮助观众理解，而不是减少文字、增加动画或让每场套用统一公式。名称保留兼容既有路由。

输入是当前 Script / Research、时间边界、Recipe、Profile、画幅、Plan 与实际预演或 Draft。只读取当前 Scene 及必要交接；不得擅改口播、时间权威、已批准语义或其他 Scene。不修改 HTML、CSS、GSAP、Three.js、音频或字幕；实现由视频工作流完成。

结果合并进现有 `ANIMATION_PLAN.md` 或 Draft QA，不新增 Motion Plan、Scene 数据库或审批。批准前允许 Work-local 同源预演；组件检索、版本、绑定和安装仍属于视频工作流。

## 先看信息，再看运动

明确观众应理解的结论，以及不可遗漏的术语、条件、步骤、例子与证据。实际上屏文字在源码或 Binding 中唯一维护，Plan 引用，不手工复制三份。信息过多先调整分组、时序和布局，确实无法放入既有音频才针对该段提出取舍。

文字负责精确解释；GSAP 负责阅读顺序、重点迁移、关系、证据放大和对象连续性；Three.js 仅用于确有价值的空间层级、路径、聚合或遮挡。不能靠删必要文字、无限缩字、让正文一直运动或装饰粒子制造“反 PPT”。

按当前内容选择表现，不强制 Hero 动词、不可逆变化、固定 Beat 数或统一入场：

| 信息需求 | 可采用的表达 | 需要保护的内容 |
|---|---|---|
| 对比工具的适用边界 | 稳定对比表，迁移焦点，局部展开当前差异 | 并列关系不能硬接成必经工作流 |
| 输入、处理与输出 | 保持对象身份，逐步改变内容并标出规则 | 输入条件、真实动作、结果与限制 |
| 解释概念与条件 | 正文按含义分组，图形关联到具体术语 | 完整解释不能只剩关键词 |
| 查看真实操作证据 | 放大相关区域，稳定注释，再回到上下文 | 不以模拟 UI 冒充真实产品能力 |
| 聚合、筛选或空间分层 | 可追踪对象与对应说明同步变化 | 为什么保留、排除或分层，不能只看见随机运动 |

标题、段落、列表、截图、卡片、对比表、箭头及稳定阅读都可以成立。静态关键帧能表达完整信息不是失败；不要求去掉文字仍能理解全部机制，也不把依赖容器组织信息作为自动重写理由。

## 阅读与隐喻

每组必要文字应在真实速度、实际显示尺寸下有稳定阅读窗口。可保留已讲内容作为上下文，下一组出现时明确焦点。复杂正文进入时降低其他区域运动；观察空间变化时说明文字可稳定留存，不必全画面静止。

不设所有 Scene 通用的字数、字体、文字占比、停留时长或结尾 `0.4s` 规则。遮挡、越界、正文漂移或被景深模糊是具体问题，不是要求所有场景采用同一布局的理由。

关键隐喻用一句话交代对象代表什么、动作映射什么关系、观众应得出什么结论。并列、比较与因果不能偷换。真实证据、模拟操作、概念示意要可区分；数字、排名、成功状态与百分比应有依据或标为演示值，没有可定义进度时不用 `0 -> 100%`。

## 预演与局部复审

所有 Scene 都应可定位和播放，关键文字、主要行为及交接实际可见。缺少关键素材时指出缺失及影响，不将占位视为获批。静态关键帧辅助阅读检查，不能替代观看运动过程；不要求无风险场景生成多个方案。

反馈定位到版本、Scene、必要时间范围或对象；先保留用户明确要求不变的文字与视觉，再提出最小有意义修改，检查受影响交接。主构图或视觉目标实质变化只回到该部分确认；easing、换行和同语义强调不新增审批。

复用区分完整叙事组件、动作/效果模块与参考经验。候选须适合真实文字长度、信息形态、画幅、时长与素材；默认一个推荐，仅存在实质取舍时比较备选。不预设整库目录或强制复用比例，不删除未来设计；改组件内部实现应派生 Work-local custom，不覆盖冻结 vendor。两次技术绑定不等于两次真实生产复用。

## 输出

只报告具体结果和必要修改：Scene/时间范围、必须保留的信息、观察到的问题、建议的文字/动作职责与阅读安排、受影响交接、未验证项。复杂场景可用时间表，不要求每场完整套表或拒绝清单。

`PASS` 表示当前可见证据未发现需要修复的问题，不代表用户已接受 Draft。`REWRITE` 仅用于缺字、错误关系、遮挡、无法阅读、关键效果未实现等实际问题，并定位到受影响内容；不能为追求 `PASS` 循环重构。审美建议与必须修复项分开，没有实质缺陷不推翻已确认方向。缺少动态证据时明确未验证，不以截图替动效验收。
